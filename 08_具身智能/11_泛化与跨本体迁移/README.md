# 11_泛化与跨本体迁移

> 让机器人策略从训练任务走向新环境、新对象、新指令和不同机器人本体。

## 本章定位

机器人已经学会把红杯放进托盘。换成带把手的高杯、把托盘移到另一张桌上，或者换一台机械臂，都可能改变结果。要判断模型能推广到哪里，先明确训练时见过哪些条件，再观察新条件下哪些能力可以复用、哪些部分需要适配。

本章从泛化维度和目标域数据预算出发，讨论多任务预训练、策略适配、动作映射与持续学习。仿真到真机的差异处理见[仿真与 Sim-to-Real](../10_仿真与Sim-to-Real/README.md)。

## 读完本章，你应该能够

- 把“泛化能力”转成可分别验证的对象、场景、任务、指令和本体变化。
- 根据目标机器人的观测、动作与物理能力确定适配范围。
- 在给定数据预算下比较预训练、微调与从头训练的收益。
- 通过新旧任务联合评测判断迁移效果和持续学习中的能力变化。

## 泛化需要明确变化的维度

泛化描述模型在训练样本之外的表现。迁移学习则利用已有模型或知识帮助目标任务学习。实际评测可以同时研究两者，例如用少量目标机器人示范微调，再测试未见杯子上的表现。

| 维度 | 红杯任务中的变化 | 测试时应核对 |
| --- | --- | --- |
| 对象 | 新杯形、尺寸、材质或重量 | 对象实例、类别及物理属性在训练中的覆盖 |
| 场景与观测 | 新房间、背景、光照或相机安装位置 | 场景与采集会话是否独立 |
| 指令 | 同义表达、不同指代或空间关系 | 是表达变化，还是目标与约束也发生变化 |
| 任务与组合 | 从放杯到整理餐具，或把已学技能组合成长流程 | 子技能和技能组合分别是否见过 |
| 本体 | 更换机械臂、夹爪、双臂或移动平台 | 目标硬件及其数据是否参与过训练 |
| 时间与运行条件 | 磨损、标定漂移、负载变化 | 测试日期、硬件状态和运行时是否有适配 |

新任务的组合泛化要求已有技能能按新的条件与顺序配合。抓杯和开柜门分别成功后，打开柜门、找到杯子再放入托盘，还会引入状态交接、遮挡和更长的执行链。可以先测单项变化，再测组合变化，逐步定位能力下降的位置。

### 零样本与少样本怎样描述？

零样本执行需要说明“零”的范围，例如没有目标任务示范，或没有目标本体上的训练轨迹。系统可能已经使用标定、接口配置或其他目标域信息，应一并披露。少样本适配应记录示范条数、时长、交互尝试及人工修订成本，便于比较不同方法。

<a id="transfer"></a>

## 多任务预训练能复用什么？

预训练可以让模型获得视觉语义、接触相关表征或已有技能的动作规律。目标域微调再用具体任务与本体数据调整行为。多来源数据可能扩大覆盖，也可能因控制语义冲突、质量差异或采样失衡降低目标表现，这种情况称为负迁移。Open X-Embodiment 通过多本体轨迹与 RT-X 实验研究跨数据集训练的收益。[Open X-Embodiment: Robotic Learning Datasets and RT-X Models](https://arxiv.org/abs/2310.08864)

判断是否值得复用，可以比较相同目标数据预算下的从头训练与预训练微调，记录目标成功率和训练成本。再改变目标数据量，观察收益如何变化。若只比较使用大量额外数据的预训练模型与数据很少的基线，应把这种数据条件差异写清楚。

<a id="embodiment"></a>

## 跨本体时，需要对齐哪些信息？

一台机械臂使用双指夹爪，另一台使用吸盘。两者可以共享「把杯子放进托盘」的目标，实际接触点、接近方向和保持方式则各有要求。

| 层面 | 需要检查的差异 | 常见处理 |
| --- | --- | --- |
| 观测 | 相机数量、视角、传感器和关节状态维度 | 输入适配器、缺失模态处理、目标域表征微调 |
| 动作接口 | 关节数、坐标系、单位、控制模式与频率 | 本体专用动作头、归一化和控制接口转换 |
| 几何与物理能力 | 可达范围、夹持方式、负载和运动限制 | 重新选择抓取方式、求解可行运动与接触约束 |
| 时序与反馈 | 延迟、接触信号和执行阶段 | 对齐动作生效时刻，调整闭环更新与成功判据 |

**动作重定向（retargeting）**将源动作或运动目标映射到目标本体，例如用关键点或末端目标重新求解关节配置。映射需要考虑可达性、自碰撞和接触关系。统一末端坐标有助于共享任务意图，具体执行仍依赖目标本体的运动学与控制。

一种通用策略可以共享骨干，并用本体条件或专用输入输出模块处理差异。Octo 展示了用预训练策略适配新观测和动作空间的做法。评估这类方法时，应查看目标本体数据与微调设置。[Octo: An Open-Source Generalist Robot Policy](https://arxiv.org/abs/2405.12213)

<a id="adaptation"></a>

## 怎样选择适配方法？

| 方法 | 主要调整什么 | 适用判断 |
| --- | --- | --- |
| 接口与动作映射 | 坐标、单位、关节顺序、动作含义 | 已有策略能力是否能在目标硬件上表达和执行 |
| 动作头或输入适配器 | 连接共享表征与目标观测、动作 | 模态或输出维度变化是否集中在接口 |
| 参数高效微调 | 用 LoRA 等方式更新部分参数 | 在目标数据预算下能否获得所需收益 |
| 全参数微调 | 更新更多表征与动作生成参数 | 域差异较大时，数据和计算是否支持稳定适配 |
| 策略蒸馏 | 用教师输出或轨迹训练学生 | 学生输入是否足够、教师信号能否映射到目标动作 |

LoRA 的低秩更新可以减少需训练的参数，实际训练内存、延迟和适配效果还受模型结构与实现影响。若变化来自夹持方式或目标观测缺失，应先检查训练信息和动作接口能否表达任务。[LoRA: Low-Rank Adaptation of Large Language Models](https://arxiv.org/abs/2106.09685)

蒸馏时，教师若依赖仿真精确状态，学生只能使用相机，需要检验学生是否能从可用观测推断教师所用信息。跨本体蒸馏还需要定义监督对应，例如监督共同任务目标、重定向轨迹或目标本体可执行动作。

后训练指初始训练之后进一步适配和改进行为的一组阶段，可以包含示范微调、奖励优化或偏好学习。偏好信号可表达「放得稳」或「动作更平缓」等要求，训练前需要明确比较标准，验证偏好是否改善实际任务结果。在线修正则可使用执行中的纠正示范或反馈，记录与评测隔离的数据范围。

<a id="continual"></a>

## 持续学习怎样保留已有技能？

模型按顺序学习新任务时，参数更新可能使旧任务表现下降，这通常称为灾难性遗忘。可以通过旧任务数据回放、约束重要参数的变化，或为新任务增加专用参数等方式缓解。数据回放需要存储和采样预算，专用模块会增加部署管理成本。参数重要性约束的代表方法 EWC 从旧任务参数的重要程度出发限制更新。[Overcoming Catastrophic Forgetting in Neural Networks](https://arxiv.org/abs/1612.00796)

每轮适配后，同时评测旧杯子、新杯子和已学任务组合。记录新任务收益、旧任务保留程度、回放数据量及适配时间。若共享骨干和专用模块都发生变化，应保留模型、模块与数据版本的对应关系。LIBERO 提供了面向持续机器人学习的任务组织与知识迁移评测实例。[LIBERO: Benchmarking Knowledge Transfer for Lifelong Robot Learning](https://arxiv.org/abs/2306.03310)

<a id="evaluation"></a>

## 一次跨本体迁移实验怎样设计？

1. **写明源域与目标域。** 记录机器人、夹爪、观测、任务和训练数据。先确认目标本体能完成所要求的操作。
2. **建立适配前基线。** 完成必需的接口配置后测量目标表现，记录哪些硬件、标定或数据已被使用。
3. **控制目标数据预算。** 比较从头训练、动作头适配和其他微调方式，保持测试起点、成功条件和重试规则一致。
4. **分组测试变化。** 依次检查新对象、新场景、新指令和技能组合，再测试同时变化的条件。
5. **报告新旧能力。** 给出试验次数、完整成功率、阶段失败、干预、适配成本及旧任务表现。

把红杯技能迁到吸盘机器人时，可以先检验杯子的可吸附表面和吸取反馈，再比较少量目标示范带来的收益。若失败集中在杯口反光导致的定位偏差，优先检查视觉适配。若定位准确却无法建立吸附，则需回查接触方式、吸力与动作监督。用这些阶段证据决定下一轮调整。

## 自检问题

1. 新杯子成功、新房间失败，应该怎样描述策略的泛化结果？
2. 跨本体任务使用了目标机器人示范后，应怎样报告适配预算？
3. 将末端目标映射给另一台机械臂，还需要检查哪些约束？
4. 为什么每轮学习新任务后都要重测旧任务？

<details>
<summary>展开参考答案</summary>

1. 分别报告对象和场景测试条件及结果，进一步定位视觉、动作或数据覆盖问题。
2. 写明轨迹数、时长、真实交互与人工投入，以及更新了哪些模块，标注为目标域适配后的结果。
3. 检查坐标系、可达性、碰撞、夹爪接触、负载和控制时序，并验证完整执行。
4. 新任务更新会影响共享参数。联合评测能够观察遗忘、正向迁移及是否需要调整回放配比。
