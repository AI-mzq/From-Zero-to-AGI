# 12_评测、安全与可靠性

> 判断机器人是否真正具备任务能力、泛化能力和可接受的物理安全边界。

## 本章定位

机器人完成了十次红杯放置，其中两次由人扶正杯子，一次碰到托盘边缘，另一次超时后重新开始。怎样统计这些结果，会直接改变我们对它能力的判断。本章从成功条件和测试协议出发，连接能力评测、执行安全和持续运行中的可靠性。

## 读完本章，你应该能够

- 为任务定义可复核的成功、失败、干预和重试规则。
- 根据证据来源解释离线、仿真和真机测试能够支持的结论。
- 从任务能力、恢复、时序和物理风险多个维度设计评测。
- 用运行记录追溯故障，并判断一次修改是否提高了整体可靠性。

<a id="protocol"></a>

## 先定义任务协议

红杯任务可以定义为“将指定杯子放入指定托盘，释放并撤离后，杯子保持直立且稳定”。还需要约定观察时间、任务超时、初始位置分布及可接受的接触。每项条件都应能通过录像、状态测量或人工复核判断。

| 协议项 | 需要写明的内容 |
| --- | --- |
| 一次尝试 | 起始状态、开始时刻、结束条件和重置方式 |
| 成功与失败 | 对象、位置、姿态、稳定性及超时等判据 |
| 干预 | 接管、扶正、重定位、修改指令分别怎样计数 |
| 重试与恢复 | 单次任务允许几次，耗时和失败是否累计 |
| 测试条件 | 本体、场景、对象、指令、速度与负载范围 |

首试成功率和允许恢复后的完成率可以分别记录。如果人扶正了杯子，应记录为人工干预，并按预先约定的协议统计。单项条件通过率也值得保留，例如选对杯子、夹持稳定和放置正确，方便定位完整任务失败的阶段。

导航评测同样依赖目标定义和终止规则。SPL 将成功与路径效率结合，适合观察导航中的效率代价。操作任务还需要按对象最终状态与接触要求定义自己的指标。[On Evaluation of Embodied Navigation Agents](https://arxiv.org/abs/1807.06757)

<a id="evidence"></a>

## 离线、仿真和真机测试提供哪些证据？

| 测试方式 | 可以观察的内容 | 还需要补充验证的环节 |
| --- | --- | --- |
| 离线数据评测 | 动作预测误差、结果判别、状态估计 | 策略自身动作引起的新状态，以及真实控制反馈 |
| 闭环仿真 | 完整执行、重置、扰动和大规模条件扫描 | 传感、控制和接触的现实差距 |
| 受控真机测试 | 真实感知、接触、延迟和本体响应 | 更广场景及长时间运行的变化 |
| 持续运行测试 | 多次任务、磨损、资源故障、恢复和人工维护 | 尚未覆盖的工作条件和事件 |

仿真与真机之间的对应性可以通过配对任务实验检验。SIMPLER 在其测试的机器人设置与任务中研究了这种对应关系。用于新本体、新任务或新模型时，还需重新核查控制、视觉和结果排序的关系。[Evaluating Real-World Robot Manipulation Policies in Simulation](https://arxiv.org/abs/2405.05941)

<a id="metrics"></a>

## 怎样同时报告能力、成本和风险？

| 维度 | 建议记录 |
| --- | --- |
| 任务能力 | 完整成功次数与总尝试数、分阶段结果 |
| 泛化与鲁棒性 | 分对象、场景和扰动条件的成功率与失败模式 |
| 恢复能力 | 可恢复事件数、恢复成功数、耗时和重复失败次数 |
| 效率与时序 | 完成时间、端到端延迟、超时、长尾延迟和资源消耗 |
| 人工投入 | 接管、重置、标定和维护的次数与时间 |
| 物理事件 | 碰撞、掉落、异常接触、保护停止及其严重程度 |

报告成功率时同时给出试验次数。不同起点或场景的多次试验可以估计不确定性，例如为成功比例报告置信区间。多帧属于同一条轨迹时，统计仍应保留轨迹或场景的分组关系。比较方法时尽量配对起点，并随机或交替安排测试顺序，以减少电量、温度和设备变化的影响。

恢复成功率的分母要明确为实际进入恢复流程的事件数。任务完成时间应包含协议允许的自动重试，人工重置耗时可以另列。对不同严重程度的事件分别计数，并记录运行时长或任务次数等暴露量，便于解释发生频率。

<a id="safety"></a>

## 执行安全怎样进入系统？

机器人动作的风险取决于本体、负载、工具、环境和人员活动。红杯滑落可能导致物体损坏，夹爪靠近人手时还存在夹伤风险。开发者需要结合实际作业条件评估后果，再选择工作空间限制、速度与力限制、监测和停止措施。

```text
任务请求 → 授权与前置条件检查 → 候选动作
→ 动作约束与执行监督 → 控制与驱动 → 真实反馈
                         ↑                 │
                         └── 异常监测 ─────┘
```

| 环节 | 主要检查 |
| --- | --- |
| 任务入口 | 对象和指令是否明确，当前操作者是否有权启动相应动作 |
| 动作执行前 | 可达范围、碰撞几何、负载、速度及当前状态是否有效 |
| 执行期间 | 观测是否过期、通信是否中断、是否出现异常接触 |
| 异常处置 | 根据本体和持物状态进入适当停止或保持状态，确认后恢复 |

监督机制需要在策略卡住或输出异常时仍能及时生效。停止过程要结合检测、通信、制动时间和测量误差检验，具体边界由设备与作业条件确定。NIST 的速度与间距监测研究讨论了相关测量因素和实施问题。[Implementing Speed and Separation Monitoring in Collaborative Robot Workcells](https://www.nist.gov/publications/implementing-speed-and-separation-monitoring-collaborative-robot-workcells)

故障测试可以从仿真、日志回放和受控装置逐步验证丢帧、失联或超时的处理。涉及人员时，应使用经过风险评估的测试方案与防护。需要认证或合规验收的系统，应按适用设备、应用场景和现行要求开展专业验证。

<a id="reliability"></a>

## 可靠性需要连续运行与恢复证据

可靠性关注系统在给定条件和时间范围内持续履行功能的能力。除每次任务结果外，可以记录无故障运行时间、故障频率、恢复时间和可用时间。报告这些量时应说明故障定义、维护安排及停机原因。

红杯连续搬运一小时后，可能出现相机遮挡、夹爪发热、标定漂移或推理资源竞争。测试可以分别覆盖连续运行、断连恢复、冷启动和版本升级。恢复时需要重新确认对象位置、夹持状态和任务进度，避免按中断前的旧状态继续发出动作。

一次修复可按以下流程复核：

1. 保存故障前后的观测、命令、时间戳、系统状态及版本。
2. 在可控条件下重现故障，确认受影响环节。
3. 修改后重测该条件，并回归正常任务和其他恢复流程。
4. 比较失败、误报停止、耗时与人工干预的变化。

频繁保护停止值得单独排查。它可能及时拦住了风险，也可能来自监测噪声或不适配的阈值。需要结合触发原因与运行结果调整，并再次验证防护效果。

<a id="reporting"></a>

## 一份可复核的评测记录应包含什么？

- **测试定义** · 任务、起点分布、成功判据、超时、重试和人工介入规则。
- **训练与适配条件** · 目标场景是否参与训练、真实示范和交互预算、评测数据的分组切分。
- **运行配置** · 硬件、标定、控制参数、模型、数据、软件与仿真版本。
- **完整结果** · 总尝试数、分条件指标、失败录像与事件记录，以及被排除试验的原因。

测试集反复参与调参后，可另设保留条件复核泛化。若基准中多数方法都接近满分，可以检查样本量、任务难度和指标分辨能力，再补充有明确含义的测试条件。排查失败时先区分目标选择、状态估计、动作生成、控制执行和系统故障，再将证据回流到相关模块。

## 自检问题

1. 杯子最终放对，但有人中途扶正，评测应该记录哪些结果？
2. 两个模型分别成功 9/10 次和 90/100 次，还应怎样比较？
3. 通信中断后，为什么恢复动作前要重新确认夹持与任务状态？
4. 修复一次掉杯故障后，应该怎样回归测试？

<details>
<summary>展开参考答案</summary>

1. 记录最终状态、人工干预、发生阶段和耗时，按预先定义的规则统计自主成功与辅助完成。
2. 核对测试条件、样本独立性和不确定性，再比较阶段失败、耗时、干预与物理事件。
3. 中断期间物体和机器人状态可能变化，旧目标和剩余动作可能已经失效。
4. 重测掉杯条件，同时检查正常任务、其他恢复流程以及是否增加误报停止或执行成本。

</details>
