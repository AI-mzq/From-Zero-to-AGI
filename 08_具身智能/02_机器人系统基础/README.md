# 02_机器人系统基础

> 看懂机器人如何把传感器数据、模型决策与物理动作连接起来，以及为什么正确的模型输出仍可能在真实系统中执行失败。

## 本章定位

机器人不是“大模型加一套机械外壳”，而是由本体、传感器、计算单元、执行器、通信链路和安全机制共同组成的实时系统。模型产生的目标或动作，只有经过坐标转换、运动规划、控制与硬件接口，才能变成物理世界中的可靠行为。

本章面向已经了解基本 AI 或大模型概念、但缺少机器人系统背景的读者，补齐后续学习具身感知、任务规划、机器人学习和 VLA 所必需的工程语言。

本章不展开机械设计、刚体运动学推导、控制器证明或 ROS 2 开发教程。更深入的感知算法、规划方法、不同机器人本体和部署工程将在后续章节分别讨论。

## 读完本章，你应该能够

- 说明本体、传感器、执行器、计算单元和安全系统分别承担什么职责。
- 区分外部感知、本体感受和交互感知，理解标定、时间戳与同步的重要性。
- 解释坐标系、位姿和坐标变换为什么是连接感知与动作的基础。
- 区分正运动学、逆运动学、动力学、路径、轨迹、规划与控制。
- 说明高层模型输出如何经过分层接口变成机器人可执行命令。
- 分析控制频率、端到端延迟、抖动和过期数据如何影响真实系统。

<a id="system-anatomy"></a>

## 一个机器人系统由哪些部分组成？

**一句话理解：机器人系统是一条从信息进入、计算决策到施加物理作用并接收反馈的完整链路。**

```text
环境
  ↓ 光、深度、声音、接触与运动
传感器
  ↓ 带时间戳的测量数据
计算与决策
  ↓ 目标、路径、轨迹或控制指令
控制器与硬件驱动
  ↓ 电流、电压、压力等驱动信号
执行器与本体
  ↓ 运动和物理作用
环境产生新状态 ──────────────→ 再次感知
```

| 组成部分 | 主要职责 | 常见对象 | 失效时的典型表现 |
| --- | --- | --- | --- |
| 本体与机械结构 | 定义形态、自由度、可达范围和承载能力 | 连杆、关节、底盘、腿、末端执行器 | 目标不可达、结构碰撞、负载不足 |
| 传感器 | 测量环境、机器人自身和接触状态 | 相机、编码器、IMU、激光雷达、力矩与触觉传感器 | 看错、定位漂移、无法判断接触 |
| 计算单元 | 运行感知、规划、模型推理与控制软件 | CPU、GPU、MCU、实时控制器 | 推理过慢、控制超时、系统中断 |
| 执行器与传动 | 把控制命令转化为运动或作用力 | 电机、液压、气动、减速器、丝杠 | 跟踪误差、过热、回差、力不足 |
| 通信与硬件驱动 | 在软件和设备之间传递状态与命令 | 总线、网络、驱动、状态与命令接口 | 丢包、数据过期、命令未执行 |
| 供电与热管理 | 向计算和执行系统稳定供能并处理热量 | 电池、电源、散热系统 | 降频、续航下降、突然断电 |
| 安全系统 | 限制危险动作并在异常时进入安全状态 | 急停、软硬限位、碰撞检测、看门狗 | 失控、碰撞或无法及时停止 |

机器人软件经常被画成感知、规划和控制三个框，但真实系统还依赖供电、通信、设备驱动和安全链。它们可能不直接提升模型能力，却决定模型能力能否稳定出现在物理世界中。

### 不同本体为什么需要不同系统设计？

| 本体类型 | 主要动作接口 | 系统关注重点 |
| --- | --- | --- |
| 固定机械臂 | 关节位置、速度或力矩；末端位姿 | 可达性、碰撞、抓取与接触控制 |
| 移动机器人 | 线速度、角速度或轮速 | 定位、路径跟踪、避障与底盘约束 |
| 移动操作机器人 | 底盘与机械臂联合命令 | 移动和操作协同、长链路误差 |
| 四足与人形机器人 | 关节目标、力矩、足端或全身目标 | 平衡、接触切换、全身协调与实时控制 |

同一个高层模型即使理解了任务，也不能跳过本体适配直接复用一套底层动作。不同本体的传感器布局、动力学和命令接口并不相同。

<a id="sensing"></a>

## 机器人怎样知道外界和自身发生了什么？

**一句话理解：机器人既要观察环境，也要测量自己的身体状态和接触结果。**

| 感知类型 | 它回答的问题 | 常见传感器或信号 | 典型局限 |
| --- | --- | --- | --- |
| 外部感知（exteroception） | 周围有什么、在哪里、如何变化？ | RGB 相机、深度相机、激光雷达、麦克风 | 遮挡、光照变化、视野限制、噪声 |
| 本体感受（proprioception） | 机器人自身处于什么状态？ | 关节位置、速度、力矩，IMU，底盘里程计 | 零点误差、漂移、机械回差 |
| 交互感知 | 机器人和环境接触得怎样？ | 六维力/力矩、触觉阵列、电机电流、碰撞信号 | 接触位置难判断、信号耦合、易受材料影响 |

以抓杯子为例，相机可以告诉机器人杯子大致在哪里；关节编码器告诉系统机械臂当前姿态；腕部力传感器和夹爪触觉则帮助判断是否已经接触、夹紧或发生滑动。只依赖其中一种信号，很难形成可靠闭环。

### 传感器输出为什么不能直接当作真实状态？

传感器提供的是测量值，不是无误差的世界真相。一项测量进入系统通常要经过：

```text
物理量 → 传感器采样 → 设备处理 → 驱动读取
→ 时间戳与坐标系标记 → 标定和滤波 → 状态估计或模型输入
```

其中有三个容易被大模型背景读者忽略的条件：

1. **标定（calibration）**：确定传感器内部参数，以及传感器相对机器人本体的位置和方向。
2. **时间戳（timestamp）**：说明数据对应的是哪个真实时刻，而不是软件何时读到它。
3. **同步（synchronization）**：让不同频率、不同延迟的相机、IMU、编码器和力觉数据对齐到可比较的时间。

如果相机图像与关节状态相差几十毫秒，系统可能把“过去看到的杯子”与“当前机械臂的位置”拼在一起。模型理解本身没有出错，组合后的状态仍然可能是错的。

> **容易混淆：** 分辨率更高不等于对控制更有用。机器人还关心采样频率、延迟、视野、噪声、动态范围、标定稳定性和数据是否及时进入闭环。

<a id="frames"></a>

## 为什么机器人必须明确坐标系和位姿？

**一句话理解：任何“位置”都必须说明相对于谁来描述，否则同一组数字没有可执行意义。**

| 坐标系 | 固定位置 | 常见用途 |
| --- | --- | --- |
| 世界或地图坐标系（world / map） | 环境中的全局参考 | 描述房间、地图、导航目标 |
| 机器人基座坐标系（base） | 机器人机身或机械臂底座 | 描述机器人附近的目标和动作 |
| 连杆与关节坐标系（link / joint） | 每段机械结构 | 建立机器人运动学模型 |
| 末端或工具坐标系（end-effector / tool） | 夹爪、吸盘或工具 | 描述抓取、接触和工具动作 |
| 传感器坐标系（camera / lidar） | 相机或其他传感器 | 表示原始测量所在参考系 |
| 物体坐标系（object） | 杯子、托盘等目标 | 表示物体姿态和操作目标 |

**位姿（pose）**由位置和方向共同组成。相机识别到杯子位于“前方 0.6 米”，还不足以驱动机械臂：系统需要知道测量来自哪个相机、相机相对基座如何安装、杯子的方向是什么，以及测量对应哪个时刻。

坐标变换通常用旋转和平移组成的齐次变换矩阵表示：

```math
{}^{A}\mathbf{T}_{B} =
\begin{bmatrix}
{}^{A}\mathbf{R}_{B} & {}^{A}\mathbf{p}_{B} \\
\mathbf{0}^{\mathsf T} & 1
\end{bmatrix}
```

多个变换可以沿坐标树连接：

```math
{}^{W}\mathbf{T}_{O}
= {}^{W}\mathbf{T}_{B}
  {}^{B}\mathbf{T}_{C}
  {}^{C}\mathbf{T}_{O}
```

这里的 $W$、$B$、$C$ 和 $O$ 分别表示世界、机器人基座、相机和物体坐标系。相机中的杯子位姿只有经过变换链，才能成为机器人基座坐标系下的抓取目标。

[ROS REP-103](https://www.ros.org/reps/rep-0103.html) 规定了常用单位和坐标轴约定，[REP-105](https://www.ros.org/reps/rep-0105.html) 定义了移动机器人常见坐标系；ROS 2 的 [tf2](https://docs.ros.org/en/rolling/Concepts/Intermediate/About-Tf2.html) 用带时间缓存的坐标树管理坐标系关系。它们解决的不是“公式怎么写”，而是不同模块如何对同一空间达成一致。

### 机器人模型记录了什么？

机器人软件需要一份结构模型，记录连杆和关节连接、关节类型与限位、碰撞几何、质量与惯量，以及传感器、工具与基座的固定关系。

在 ROS 生态中，[URDF](https://docs.ros.org/en/rolling/Tutorials/Intermediate/URDF/URDF-Main.html) 是描述机器人几何与组织结构的常用格式。机器人模型不是外观图，而是状态发布、碰撞检测、运动学求解和控制接口共享的结构依据。

<a id="motion-basics"></a>

## 运动学和动力学分别解决什么问题？

**一句话理解：运动学研究“怎样运动到那里”，动力学进一步研究“需要怎样的力才能按预期运动”。**

**自由度（degree of freedom, DoF）**表示描述机器人独立运动所需的变量数量。机械臂常用关节角或关节位移组成向量 $\mathbf q$。自由度更多可以增加灵活性，也会扩大搜索空间、控制难度和碰撞风险。

| 问题 | 已知 | 求解 | 关键限制 |
| --- | --- | --- | --- |
| 正运动学（forward kinematics） | 关节变量 $\mathbf q$ | 末端位姿 $\mathbf x$ | 通常直接计算 |
| 逆运动学（inverse kinematics, IK） | 目标末端位姿 $\mathbf x_d$ | 可行关节变量 $\mathbf q$ | 可能无解、多解或接近奇异位形 |
| 速度运动学 | 关节速度 $\dot{\mathbf q}$ 或末端速度 $\dot{\mathbf x}$ | 二者之间的映射 | 受雅可比矩阵和奇异性影响 |

```math
\mathbf x = f(\mathbf q),
\qquad
\dot{\mathbf x} = \mathbf J(\mathbf q)\dot{\mathbf q}
```

正运动学 $f$ 把关节状态映射到末端位姿；雅可比矩阵 $\mathbf J$ 描述局部速度关系。逆运动学从目标位姿反推关节配置，但求得一个关节解并不意味着已经获得安全、平滑、可执行的运动轨迹。

运动学不关心质量、惯量、重力、摩擦和外力。真实机器人在加速、搬运或接触物体时，这些因素会决定所需驱动力以及动作是否稳定。机械臂动力学常被概括为：

```math
\boldsymbol{\tau}
= \mathbf M(\mathbf q)\ddot{\mathbf q}
+ \mathbf C(\mathbf q, \dot{\mathbf q})\dot{\mathbf q}
+ \mathbf g(\mathbf q)
+ \boldsymbol{\tau}_{\mathrm{friction}}
```

其中 $\boldsymbol{\tau}$ 是关节力矩，$\mathbf M$、$\mathbf C$、$\mathbf g$ 和 $\boldsymbol{\tau}_{\mathrm{friction}}$ 分别表示惯性、速度耦合、重力和摩擦影响。本章不要求推导公式，只需理解：**相同目标位姿在不同负载、速度和接触条件下，需要的控制作用并不相同。**

Kevin Lynch 与 Frank Park 的 [*Modern Robotics: Mechanics, Planning, and Control*](https://hades.mech.northwestern.edu/index.php/Modern_Robotics) 系统讲解了刚体运动、运动学、动力学、规划与控制，可作为后续学习入口。

<a id="control-stack"></a>

## 规划、轨迹和控制为什么不能混为一谈？

**一句话理解：规划决定希望机器人怎样到达目标，控制负责让真实机器人持续跟上这项安排。**

| 层级 | 主要问题 | 典型输出 | 直接驱动硬件？ |
| --- | --- | --- | :---: |
| 任务理解与高层策略 | 要完成什么、先做什么？ | 技能调用、子任务、目标物体 | 否 |
| 任务规划 | 多个技能怎样排序并满足前置条件？ | 抓取、移动、放置等步骤 | 否 |
| 运动规划 | 在约束和障碍物下如何运动？ | 几何路径或候选运动 | 否 |
| 轨迹生成 | 每个时刻应处于什么状态？ | 带时间参数的位置、速度、加速度序列 | 通常否 |
| 反馈控制 | 当前状态偏离目标时如何修正？ | 位置、速度或力矩命令 | 是或接近硬件层 |
| 硬件驱动 | 怎样发送命令并读取设备状态？ | 电机、电流或总线指令 | 是 |

- **路径（path）**描述机器人在空间中经过哪些位置或构型，主要回答“从哪里走”。
- **轨迹（trajectory）**加入时间参数，并规定速度和加速度，回答“何时到达、以多快速度运动”。

无碰撞路径如果没有合理时间参数，仍可能因为速度过高、加速度不连续或执行器能力不足而无法执行。MoveIt 的[运动规划文档](https://moveit.picknik.ai/main/doc/concepts/motion_planning.html)也把路径规划、约束检查和时间参数化放在规划管线中处理。

### 高层模型可以输出哪一层动作？

| 模型输出 | 示例 | 下游系统仍需完成什么？ |
| --- | --- | --- |
| 技能或子任务 | “抓取红色杯子” | 目标定位、运动规划、控制和反馈 |
| 末端位姿或路点 | 夹爪移动到杯子上方 | 逆运动学、碰撞检查、轨迹与控制 |
| 关节目标 | 下一时刻各关节位置 | 限位检查、插值、反馈控制 |
| 动作块或短轨迹 | 未来若干步动作序列 | 滚动执行、状态更新和必要的重规划 |
| 低层控制量 | 关节速度或力矩 | 高频安全约束和硬件执行 |

模型输出越接近底层，承担的实时性、稳定性和安全责任通常越高；输出越接近高层，对传统规划和控制模块的依赖通常越强。比较机器人模型时，不能只看“是否输出动作”，还要看它输出的是哪一层动作、以什么频率执行、下游有哪些保护模块。

## 状态接口和命令接口连接了什么？

**一句话理解：状态接口把硬件真实情况送入软件，命令接口把软件目标交给硬件，两者的语义必须严格一致。**

| 接口类型 | 状态接口提供什么 | 命令接口要求什么 | 常见风险 |
| --- | --- | --- | --- |
| 位置（position） | 当前关节角或位移 | 目标关节角或位移 | 跳变目标、超限、插值不足 |
| 速度（velocity） | 当前角速度或线速度 | 目标速度 | 长时间命令导致漂移或碰撞 |
| 力矩/作用力（effort） | 估计或测得的力矩、力 | 目标力矩、力或电流 | 对模型误差和安全机制更敏感 |

[ros2_control 的硬件接口](https://control.ros.org/master/doc/ros2_control/hardware_interface/doc/hardware_interface_types_userdoc.html)把关节状态和命令抽象为明确接口。无论是否使用 ROS，这种“状态只读、命令可写、接口语义清晰”的边界都适用于机器人系统。

可执行接口至少应明确物理量、单位、坐标系、时间戳、更新频率、允许延迟、数值范围和异常处理。如果模型按弧度输出，而硬件按角度解释；或者模型给出末端坐标，而驱动期待关节速度，即使数值合理，也会产生完全错误的动作。

<a id="timing-safety"></a>

## 为什么机器人系统通常是多频率系统？

**一句话理解：语义决策、感知、规划和底层控制的计算成本与时限不同，不能强行运行在同一个节拍上。**

下面的范围只用于形成数量级直觉，不是所有机器人的固定标准：

| 系统层级 | 常见节拍示意 | 为什么不同 |
| --- | --- | --- |
| 语言理解与高层决策 | 亚赫兹到数赫兹 | 推理较重，但目标变化较慢 |
| 视觉感知与状态估计 | 数十到数百赫兹 | 需要跟踪环境和本体状态 |
| 运动规划与滚动重规划 | 数赫兹到数十赫兹 | 计算约束多，按任务动态更新 |
| 关节或全身反馈控制 | 数百赫兹到千赫兹量级 | 必须及时抑制误差和扰动 |
| 设备内部电流或电机环 | 通常高于上层控制 | 直接控制执行器快速动态 |

高层模型可以低频给出目标，低层控制器在两次高层更新之间继续稳定执行；当新观测显示目标移动或动作失败时，系统再触发局部修正或重新规划。

### 延迟、抖动和实时性有什么区别？

- **延迟（latency）**：信息从产生到被使用所经历的时间。
- **抖动（jitter）**：延迟或执行周期随时间产生的不稳定变化。
- **截止时间（deadline）**：某项计算或动作必须完成的最晚时刻。
- **实时性（real-time）**：能否在规定时间内以可预测方式完成任务，不只是平均速度是否足够快。

```math
L_{\mathrm{total}}
= L_{\mathrm{sense}}
+ L_{\mathrm{transport}}
+ L_{\mathrm{estimate}}
+ L_{\mathrm{plan}}
+ L_{\mathrm{command}}
+ L_{\mathrm{actuate}}
```

平均延迟很低，但偶尔出现较大抖动，仍可能让控制周期错过截止时间。ROS 2 的[实时系统设计说明](https://design.ros2.org/articles/realtime_background.html)也强调，实时系统关注可预测的完成时限，而不只是“运行得快”。

不同频率的模块需要可靠时间戳、数据缓存与插值、状态和命令过期检查、通信看门狗、异常降级，以及可回放的观测—状态—命令日志。[ros2_control 的控制器管理文档](https://control.ros.org/jazzy/doc/ros2_control/controller_manager/doc/userdoc.html)也把低抖动和确定性作为硬件控制的重要要求。

## 安全机制为什么不能交给模型临场判断？

**一句话理解：安全约束必须有独立、确定且能够及时生效的执行路径。**

| 安全层 | 典型机制 | 主要防护对象 |
| --- | --- | --- |
| 机械与电气层 | 物理限位、保险、急停、制动 | 断电、过载和硬件极限 |
| 驱动与控制层 | 位置、速度、力矩限制，跟踪误差监测 | 异常命令和控制失稳 |
| 规划层 | 自碰撞与环境碰撞检查、禁入区 | 路径和姿态风险 |
| 系统层 | 看门狗、心跳、通信超时、状态机 | 模块卡死、丢包和数据过期 |
| 人机协作层 | 速度与距离限制、人工接管、权限边界 | 人员和高风险操作 |

模型可以参与风险判断，但不应成为唯一安全屏障。即使高层模型卡住、输出异常或网络断开，底层系统仍应能够拒绝越界命令、减速、保持或停止。

## 贯穿示例：把红色杯子放入托盘

继续使用上一章的移动机械臂任务：

> 用户要求机器人：“把桌上的红色杯子放入托盘。”

| 阶段 | 机器人系统发生了什么 | 关键接口或约束 |
| --- | --- | --- |
| 采集观测 | RGB-D 相机获得图像和深度，编码器报告关节状态 | 时间戳、相机参数、同步 |
| 估计目标 | 感知模块得到杯子在相机坐标系中的位姿 | 噪声、遮挡、置信度 |
| 坐标转换 | 将杯子位姿转换到机器人基座坐标系 | 坐标树、外参、测量时刻 |
| 检查可达 | 根据机器人模型、关节限位和障碍判断是否可抓 | 可达空间、碰撞几何 |
| 求解与规划 | 逆运动学生成候选配置，规划器搜索无碰撞路径 | 多解、奇异性、碰撞检查 |
| 生成轨迹 | 为路径加入时间、速度和加速度约束 | 执行器能力、平滑性 |
| 闭环执行 | 控制器比较目标与真实关节状态，持续修正 | 控制频率、延迟、跟踪误差 |
| 接触与抓取 | 力觉、触觉或电机状态判断接触和夹持 | 力限制、滑动、物体损伤 |
| 移动与放置 | 底盘、机械臂和夹爪分层协调 | 多控制器同步、动态避障 |
| 结果确认 | 相机与夹爪状态确认杯子是否进入托盘 | 成功条件、失败恢复 |

“识别杯子”和“决定抓杯子”只覆盖系统链路的一部分。真实机器人还必须让每一段数据和命令在正确坐标系、正确时间、正确接口和安全边界内传递。

## 常见故障与排查思路

| 现象 | 优先检查 | 常见根因 |
| --- | --- | --- |
| 相机看对了，机械臂却抓向错误位置 | 坐标系、外参和时间戳 | 变换错误，使用了过期位姿 |
| 规划器有结果，机器人却不运动 | 命令接口、控制模式和安全状态 | 接口不匹配，控制器未激活，急停未释放 |
| 仿真轨迹正常，真机抖动或超调 | 控制周期、动力学参数和负载 | 延迟、摩擦、增益或负载估计不准 |
| 偶尔正常、偶尔突然失败 | 抖动、丢包、异步数据和资源竞争 | 平均延迟正常但尾部延迟过大 |
| 已经接触物体，夹爪仍继续用力 | 力觉、触觉和停止条件 | 没有接触反馈、阈值不合理或数据延迟 |
| 模型输出合理，却被系统拒绝 | 限位、碰撞、安全规则和动作语义 | 目标不可达、越界或单位不一致 |

排查时应先检查数据是否新鲜、单位和坐标系是否一致，再检查状态估计、规划结果、命令接口和安全状态。直接怀疑“大模型能力不够”，往往会掩盖更基础的系统错误。

## 常见误区

### 误区一：逆运动学求出关节角，机器人就能执行

逆运动学只给出候选关节配置。系统仍需检查限位、奇异性、碰撞、路径连续性、速度与加速度限制，并生成可跟踪轨迹。

### 误区二：所有模块使用同一组三维坐标即可

数值相同不代表参考系相同。感知、地图、基座、工具和物体坐标系必须通过明确变换连接，并与时间戳对应。

### 误区三：控制频率越高，系统一定越好

频率只有在计算按时完成、传感器和执行器支持、延迟与抖动受控时才有意义。过高频率可能造成资源竞争或持续使用旧数据。

### 误区四：平均推理速度足够快，就满足实时要求

实时系统还关心最坏情况延迟、抖动和截止时间。偶发的一次长尾延迟，就可能让机器人使用过期状态继续运动。

### 误区五：仿真能执行，真机就只差部署

仿真通常简化摩擦、回差、柔性、噪声、通信和安全限制。真机还需要标定、系统辨识、控制调试和故障处理。

### 误区六：大模型可以替代全部传统机器人模块

大模型可以参与任务理解、状态推理、规划或动作生成，但坐标变换、碰撞检查、高频反馈控制、硬件驱动和独立安全链仍然具有明确价值。模块边界可以变化，物理约束不会因此消失。

## 本章速记

- 机器人是由本体、传感器、计算、执行器、通信、供电和安全机制组成的完整系统。
- 外部感知描述环境，本体感受描述机器人自身，交互感知描述接触结果。
- 传感数据必须携带正确的标定、坐标系和时间信息，才能进入同一个闭环。
- 位姿必须相对于明确坐标系描述；坐标变换链连接了感知结果与可执行目标。
- 正运动学从关节状态计算末端位姿，逆运动学从目标位姿寻找关节配置；关节解不等于轨迹。
- 动力学决定质量、惯量、重力、摩擦和接触如何影响运动与驱动力。
- 规划产生目标、路径或轨迹，控制器利用反馈持续减小真实状态与目标之间的误差。
- 模型输出越接近底层，承担的实时性、稳定性和安全责任通常越高。
- 机器人是多频率系统；实时性关注可预测的截止时间，不能只看平均速度。
- 安全约束需要独立、确定且能够及时生效的执行路径。

## 自检问题

1. 为什么完整机器人系统不能只画成“传感器—大模型—电机”？
2. 外部感知、本体感受和交互感知分别提供什么信息？
3. 为什么相机中的杯子坐标不能直接作为机械臂抓取目标？
4. 正运动学、逆运动学和动力学分别解决什么问题？
5. 路径和轨迹有什么区别？为什么无碰撞路径仍可能无法执行？
6. 高层模型输出技能、末端位姿或关节力矩时，下游职责有什么变化？
7. 为什么低平均延迟不等于满足实时要求？
8. 当“相机看对了但机械臂抓偏”时，应优先排查哪些环节？
9. 为什么机器人安全不能只依赖模型判断？

<details>
<summary>展开参考答案要点</summary>

1. 完整系统还需要状态估计、坐标变换、规划、控制、硬件驱动、供电、通信和独立安全机制；任何一环失效都可能让正确决策无法执行。
2. 外部感知描述环境对象和变化；本体感受描述关节、机身与运动状态；交互感知描述接触力、触觉和滑动等作用结果。
3. 杯子坐标属于相机参考系，并对应特定时刻。系统需要利用相机外参和坐标树将其转换到机器人基座或工具坐标系，并保证数据没有过期。
4. 正运动学由关节状态计算末端位姿；逆运动学由目标位姿寻找关节配置；动力学研究质量、惯量、重力、摩擦和外力如何决定运动与驱动力。
5. 路径只描述经过哪些位置或构型，轨迹还包含时间、速度和加速度。路径即使无碰撞，也可能超出执行器能力。
6. 输出越高层，下游越需要完成定位、规划和控制；输出越底层，模型越直接承担动作连续性、实时性和安全责任。
7. 实时系统要求任务在截止时间前可预测地完成。较低平均延迟可能掩盖偶发长尾延迟和周期抖动。
8. 优先检查目标与机器人状态的时间戳、相机外参、坐标变换链、单位、机器人模型和控制执行时刻，再判断模型语义是否出错。
9. 模型可能延迟、卡住或输出异常；底层限位、碰撞检测、看门狗和急停必须在模型失效时仍能独立生效。
