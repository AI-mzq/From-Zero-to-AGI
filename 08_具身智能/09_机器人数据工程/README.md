# 09_机器人数据工程

> 理解机器人数据从采集、组织、清洗到训练和回流的完整生命周期。

## 本章定位

两段抓杯视频看上去都很顺利。第一段保留了相机曝光时间、关节状态、夹爪命令和任务结果，第二段只有录屏。前者可以在核对时序后形成动作监督，后者可以提供视觉和任务进展线索。可训练的信息取决于采集时留下了什么，以及这些信息怎样对应。

本章沿着一次“把红杯放进左侧托盘”的执行记录，说明数据如何经过采集、对齐、质检、切分和版本管理进入训练，再由部署失败决定下一轮补采。训练方法见[机器人学习基础](../05_机器人学习基础/README.md)，仿真迁移见[仿真与 Sim-to-Real](../10_仿真与Sim-to-Real/README.md)。

## 读完本章，你应该能够

- 根据训练目标选择采集来源，并明确记录所需的监督信息。
- 解释一段执行记录怎样形成时序一致的观测—动作样本。
- 为多本体数据制定语义约定、质检和数据集切分规则。
- 从部署失败出发设计补采，并追溯训练所使用的数据版本。

## 数据来源与任务覆盖

采集计划应从预期部署条件展开。红杯任务至少涉及杯子位置、托盘位置、遮挡、光照、夹持失败和重新对准。每次都在固定位置重复成功操作，会增加轨迹数量，也会让位置与任务标签高度相关。

| 来源 | 典型价值 | 使用前要确认的信息 |
| --- | --- | --- |
| 真机遥操作与人工引导 | 提供与实际传感器和动作接口对应的示范 | 操作者、控制模式、动作时序、接管区间 |
| 策略自主执行 | 暴露当前策略常见的失败和恢复状态 | 策略版本、任务结果、干预与异常事件 |
| 仿真交互 | 批量生成对象、布局、动作及状态真值 | 仿真参数、随机种子、物理和传感器假设 |
| 人类或互联网视频 | 学习对象、任务进展和视觉表征 | 数据来源、使用许可、是否存在动作对应信息 |
| 合成或增强数据 | 扩充外观、场景及部分状态变化 | 生成方法、标签是否仍有效、物理一致性 |

遥操作可以使用手柄、主从机械臂或其他设备，操作命令往往经过缩放和滤波后才到达机器人。录制时应保存足以解释最终动作的控制信息。跨场景采集还需要一致的安装和标定约定，便于区分环境变化与设备变化。DROID 展示了分布式真机采集及配套硬件、策略训练的组织方式。[DROID: A Large-Scale In-The-Wild Robot Manipulation Dataset](https://arxiv.org/abs/2403.12945)

<a id="episodes"></a>

## 一次执行怎样组织成数据？

Episode 通常表示有明确起止边界的一次任务尝试，其中的轨迹是按时间排列的观测、动作和其他信号。一次尝试可能成功、失败、超时或被人工中断。终止原因应单独保留，方便训练程序解释样本。

| 范围 | 示例字段 | 用途 |
| --- | --- | --- |
| Episode 元数据 | 任务、机器人和场景 ID、采集时间、标定版本、操作者或策略版本 | 分组、追溯和解释记录 |
| 逐步观测 | 相机帧、关节状态、末端位姿、力觉或触觉、各自时间戳 | 形成策略输入及状态转移 |
| 动作记录 | 下发命令、控制模式、参考系、命令时间和反馈状态 | 构造动作监督，核查是否实际生效 |
| 标签与事件 | 成功、失败原因、接管区间、阶段边界、奖励与终止原因 | 按训练目标选择样本和监督 |

动作块应在 episode 内按约定生成。接近尾部时，剩余步数不足，需要使用明确的截断、填充和掩码规则，防止把下一次尝试的动作拼进当前样本。RL 还需要区分任务终止和超时截断，以决定后继价值如何处理。具体格式有自己的边界约定，例如 RLDS 的最后一步包含最终观测，其动作等后续字段按规范视为无效。[RLDS 数据结构说明](https://github.com/google-research/rlds)

## 时间对齐和动作语义怎样确认？

相机、编码器和控制器通常以不同频率运行。需要明确一条训练样本使用的是哪个观测，以及对应哪一次命令。可追溯的时间信息包括采样或曝光时刻、接收时刻、命令下发时刻和可观测的执行反馈。设备时钟还可能存在偏移和漂移。

1. **统一时间基准。** 核对设备时钟及其换算方法，记录丢帧、时钟重置和异常时间间隔。
2. **定义样本对应关系。** 例如用决策时刻可获得的观测预测之后下发的目标。转换程序应遵守这一约定，避免使用未来帧作为当前输入。
3. **按信号含义重采样。** 连续关节状态可以按规则插值，夹爪开合或接管事件需要保留离散变化。旋转插值还需尊重所用表示的几何性质。
4. **回放关键动作。** 检查接近、闭合、抬升和释放时的图像、状态与命令是否对应，并把估计的延迟记录下来。

例如夹爪闭合命令发出后，画面过一段时间才出现接触。若直接按视频帧号拼接命令，可能让模型学到过早或过晚闭合。调整对齐规则后，应通过同一片段回放验证。

跨机器人合并还需要核对关节顺序、角度单位、末端参考系、绝对目标与增量、夹爪正负方向和控制频率。统一字段名后仍应保留来源与转换记录，供本体适配时查询。Open X-Embodiment 提供了多来源机器人轨迹组织与跨本体训练的实例。[Open X-Embodiment: Robotic Learning Datasets and RT-X Models](https://arxiv.org/abs/2310.08864)

<a id="quality"></a>

## 质量控制与数据集切分

| 检查 | 典型问题 | 处理方式 |
| --- | --- | --- |
| 文件与字段完整性 | 视频损坏、观测缺失、字段维度不一致 | 标记受影响的范围，隔离样本并保留原因 |
| 数值与时序 | NaN、跳变、重复时间戳、长时间丢帧 | 结合原始信号定位，再决定修复或排除 |
| 动作与标签语义 | 夹爪方向反了、任务文字写错、结果未确认 | 回查元数据和任务录像，修订标签并记录版本 |
| 任务覆盖 | 单一对象、固定站位、缺少纠偏过程 | 补采对应条件，检查标签与布局之间的相关性 |
| 训练适用性 | 失败尝试被当作成功动作示范 | 按学习目标筛选阶段并设置相应标签或掩码 |

失败轨迹可以用于结果判别、动力学学习或带奖励的策略训练。行为克隆若要学习纠正，应核实失败后的纠正动作确实有效。一次失败尝试中，也可能存在完整可靠的接近阶段，可以按阶段处理。数据清洗时保留原始记录，训练视图记录筛选结果和理由。

切分应围绕要测试的能力分组。按 episode 分组可以防止相邻帧交叉，测试新场景或新对象时还要按场景、对象或采集会话划分。增强样本、切出的子轨迹和重新标注的副本应随其原始记录进入同一集合。归一化统计量从训练集计算，验证与测试沿用训练阶段的变换。

<a id="versions"></a>

## 存储格式与版本管理

机器人数据常把大体积视频与结构化数值分开存储，再通过索引连接。选择格式时需要验证能否按 episode 和时间窗口读取、能否检查缺失值、是否保留单位与动作语义。RLDS 侧重 episode 和 step 结构，LeRobotDataset 将表格、视频及元数据组织为可加载的数据集。采用格式前应核对对应版本的字段和读取约定。[LeRobotDataset 官方文档](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)

一次可复现的训练数据发布至少包含原始来源标识、文件校验信息、格式和转换版本、筛选规则、切分清单、归一化统计量及来源许可。训练记录还应关联采样配比和读取配置。修订了时间偏移或动作缩放后，发布新的派生版本，并保留与原始记录的关系。

<a id="feedback"></a>

## 数据混合与失败回流

混合数据前先决定采样单位。按帧采样会给较长轨迹更多权重，按 episode 采样也需要规定 episode 内如何取窗口。来源的原始数量和训练时的采样权重共同决定模型实际看到的分布，应同时记录。

以红杯任务为例，如果多数失败发生在杯子靠近托盘边缘时，可以先固定模型和测试条件，补采这一范围的接近、调整与成功放置。比较不同配比时使用同一组独立评测，再检查原有场景表现是否退化。合成数据和高频重复轨迹也按实际覆盖与闭环收益评估。

```text
部署回放 → 归因失败条件 → 设计补采 → 对齐与质检
→ 发布新数据版本 → 固定条件训练评测 → 检查补采收益
```

出现新的失败时，先看它来自目标覆盖、时序、动作接口还是执行条件。例如换了坐标变换后开始抓偏，需要回查转换过程。对齐规则修正后再决定是否补采，能让采集投入对应到具体缺口。

## 自检问题

1. 两段相同长度的抓杯视频，为什么可能具有不同的动作训练价值？
2. 相机和控制器频率不同时，构造观测—动作样本需要明确哪些约定？
3. 一段最后掉杯的轨迹可以怎样使用？
4. 为什么按帧随机切分容易高估测试结果？
5. 修订动作缩放后，怎样让旧实验仍然可追溯？

<details>
<summary>展开参考答案</summary>

1. 动作监督依赖本体状态、命令和时序记录。只有视频时可用的信息和训练目标不同。
2. 明确时间基准、可用观测、命令对应时刻、重采样方式，以及缺失或终止位置的处理。
3. 可以标注失败结果用于判别或动力学学习，也可挑出可靠阶段。训练恢复行为时要验证纠正动作及其结果。
4. 相邻帧高度相关，同一场景或轨迹副本进入测试集后，会降低实际测试难度。
5. 保留原始记录，为转换程序和派生数据发布新版本，并记录每次训练使用的版本与配置。
