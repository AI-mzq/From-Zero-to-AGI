# 03_具身感知与空间智能

> 让机器人不只“看见画面”，而是持续建立能够支持定位、导航、抓取与交互的空间状态。

## 本章定位

图像识别通常关心“画面里有什么”，具身感知还必须回答更多与行动直接相关的问题：目标在哪里、朝向如何、是否被遮挡、周围空间能否通过、哪个表面可以接触，以及机器人当前判断有多可靠。

因此，具身感知不是一个单独的视觉模型，而是一条从多传感器观测到任务状态的处理链。它需要把 RGB、深度、点云、惯性、本体状态、力觉与触觉等信号组织起来，形成能够被导航、操作和决策模块查询、更新和验证的空间表示。

本章从任务与能力出发，建立以下四层认识：

```text
感知任务 → 空间表示 → 行动语义 → 闭环验证
```

本章不展开具体网络结构、SLAM 推导、三维重建工程教程，也不讨论如何搜索路径、生成抓取轨迹或训练动作策略。这些内容分别属于视觉与三维感知算法、[导航、操作与任务规划](../04_导航操作与任务规划/README.md)、[机器人学习基础](../05_机器人学习基础/README.md)和后续模型章节。

## 读完本章，你应该能够

- 解释具身感知与普通图像识别的差别，以及“面向行动的状态表示”意味着什么。
- 说明 RGB、深度、点云、本体状态、力觉和触觉各自能提供什么信息，又有哪些盲区。
- 区分检测、分割、跟踪、深度估计、姿态估计与场景理解等任务的输出。
- 比较点云、体素、占据地图、表面模型、语义地图和场景图的用途。
- 理解定位、建图、空间记忆与动态更新之间的关系。
- 解释可供性、开放词汇感知和主动感知为什么能够连接“看见”与“行动”。
- 根据下游任务选择感知输出和评测指标，而不是只比较单个模型的离线精度。
- 从标定、同步、遮挡、漂移、不确定性和分布变化等角度分析系统失败。

<a id="what-is-spatial-intelligence"></a>

## 什么是面向机器人的空间智能？

**一句话理解：空间智能是机器人建立、更新并查询任务相关空间状态，以支持行动和验证结果的能力。**

空间智能不等于把场景重建得足够逼真。一个高保真三维模型可能适合展示，却不一定能直接回答机器人最关心的问题：

- 前方哪些区域可通行，哪些区域仍然未知？
- 杯子相对机械臂、桌面和托盘分别在哪里？
- 杯把是否被遮挡，当前视角能否可靠估计抓取位姿？
- 抽屉处于打开还是关闭状态？
- 物体移动后，地图中的旧位置是否已经失效？
- 下一步移动相机或身体，能否减少关键不确定性？

可以把空间智能理解为三种能力的组合：

| 能力 | 需要回答的问题 | 对行动的价值 |
| --- | --- | --- |
| 建立表示 | 环境中有哪些对象、表面、空闲区域和关系？ | 为定位、避障、抓取和交互提供状态 |
| 持续更新 | 机器人移动、物体变化或出现新观测后，哪些信息需要修正？ | 避免使用过期地图和错误对象状态 |
| 按需查询 | 当前任务真正需要什么空间信息？ | 减少无关计算，把感知输出对接到下游模块 |

因此，空间表示没有脱离任务的统一最优解。移动导航关注可通行空间和障碍，机械臂抓取关注物体表面、位姿与接触区域，语言任务还需要对象名称、属性和关系。系统应根据下游查询选择表示，而不是追求“越稠密、越复杂越好”。

<a id="observations"></a>

## 机器人从哪里获得空间信息？

**一句话理解：任何单一传感器都只提供世界的一种投影，多源感知的目的不是堆数据，而是互补盲区。**

| 观测来源 | 主要提供的信息 | 典型优势 | 典型局限 |
| --- | --- | --- | --- |
| RGB 相机 | 颜色、纹理、边缘和语义线索 | 信息丰富、成本较低、便于使用视觉基础模型 | 缺少直接尺度，受光照、反射和遮挡影响 |
| 深度相机 | 每个像素附近的距离 | 便于恢复局部几何和前景背景关系 | 量程、材质、阳光和遮挡会造成空洞或噪声 |
| 激光雷达 | 距离采样与空间结构 | 测距稳定、覆盖范围较大 | 点云可能稀疏，语义信息有限，存在扫描时序 |
| IMU | 线加速度与角速度 | 频率高，可补偿快速运动 | 长时间积分会漂移，需要与其他传感器融合 |
| 编码器与本体状态 | 关节位置、速度和机器人自身构型 | 直接描述身体状态 | 无法单独说明外界对象和接触结果 |
| 力觉与力矩 | 交互力、载荷和碰撞线索 | 能判断接触强度和受力变化 | 空间分辨率有限，信号受结构和控制影响 |
| 触觉传感器 | 局部接触形状、压力、滑动和材质线索 | 能观察视觉遮挡下的接触状态 | 只有接触后才能获得，覆盖范围和耐久性受限 |

### 外部感知、本体感受与交互感知

从信息作用看，传感器可以分为三组：

- **外部感知**描述环境，例如图像、深度、点云和声音。
- **本体感受**描述机器人自身，例如关节、机身姿态、速度和电机状态。
- **交互感知**描述机器人与环境之间的作用，例如接触、力、压力和滑动。

三类信息必须在同一时间与空间关系下解释。相机看到的杯子位置，需要结合当时的机器人姿态转换到基座坐标系；夹爪检测到接触，还需要与物体区域和动作阶段对应，才能判断是抓住杯子、碰到桌面还是发生侧滑。

### 多传感器融合先解决什么？

融合之前，系统至少要处理三个基础问题：

1. **空间对齐：**各传感器相对于机器人和彼此的位置、朝向是否已标定？
2. **时间对齐：**这些观测是否来自足够接近的时刻？快速运动时，毫秒级差异也会转化为空间偏差。
3. **不确定性对齐：**不同测量的噪声、缺失和置信度是否被合理建模？

如果这三点没有解决，把更多模态送进同一个模型只会让错误更难排查。融合可以发生在原始数据、特征或决策层，但选择哪一层，应由传感器频率、计算成本、标定精度和任务需求共同决定。

<a id="perception-tasks"></a>

## 感知任务分别在回答什么？

**一句话理解：检测、分割、跟踪和位姿估计并不是同一任务的不同精度版本，它们回答的是不同问题。**

| 感知任务 | 它回答的问题 | 典型输出 | 对机器人行动的作用 |
| --- | --- | --- | --- |
| 分类 | 这是什么？ | 类别或语义特征 | 选择对象类别相关的技能 |
| 目标检测 | 什么对象大致在哪里？ | 2D / 3D 边界框 | 快速发现和粗定位目标 |
| 语义分割 | 每个位置属于哪一类？ | 像素或点级类别 | 区分地面、墙体、桌面和障碍 |
| 实例分割 | 哪些区域属于同一个对象实例？ | 实例掩码 | 分离相邻同类物体，估计对象轮廓 |
| 跟踪 | 不同时刻看到的是不是同一对象？ | 对象身份与轨迹 | 维护动态状态，避免重复计数 |
| 深度估计 | 表面离传感器有多远？ | 深度图或距离 | 恢复尺度、几何和前后关系 |
| 场景流 / 光流 | 场景或像素怎样运动？ | 2D / 3D 运动场 | 预测动态物体与相对运动 |
| 6D 位姿估计 | 物体在三维空间中的位置和朝向是什么？ | 三维平移与三维旋转 | 对齐抓取、插接和工具操作 |
| 场景理解 | 对象、区域和关系构成什么情境？ | 属性、关系、场景状态 | 支持语言落地、任务判断和异常检测 |

边界框足以支持“画面中是否有杯子”，却通常不足以完成稳定抓取。抓取还可能需要实例掩码、深度、物体朝向、可见表面和不确定性。反过来，巡视机器人只需避开障碍时，也未必值得为每个对象生成精细网格。

### 2D、3D 与 4D 分别意味着什么？

- **2D 感知**在图像平面上描述像素、区域和对象。
- **2.5D 表示**通常为当前视角中的每个像素附加深度，但不完整表达被遮挡表面。
- **3D 感知**把对象和几何放入三维坐标系，支持距离、体积、方向与可达性判断。
- **4D 感知**通常指随时间变化的三维场景，即在 3D 上继续描述运动、身份和状态变化。

“升到更高维”并不会自动获得更强智能。时间同步错误会破坏 4D 关联，坐标漂移会让多帧 3D 信息重影，错误语义也会在地图中被长期保留。

<a id="spatial-representations"></a>

## 空间信息应该怎样表示？

**一句话理解：表示方式决定机器人能够高效回答哪些问题，也决定需要付出怎样的存储、计算和更新成本。**

| 表示 | 基本单位 | 擅长回答 | 主要代价或局限 |
| --- | --- | --- | --- |
| 深度图 / 高度图 | 像素或平面网格 | 当前视角距离、地面高度、局部障碍 | 视角依赖，遮挡区域信息缺失 |
| 点云 | 三维采样点 | 表面在哪里、局部形状如何 | 稀疏且无显式表面连接，密度不均 |
| 体素 / 占据地图 | 三维网格单元 | 哪些区域空闲、占据或未知 | 分辨率越高，存储和计算越昂贵 |
| TSDF / 距离场 | 到表面的截断或有符号距离 | 表面融合、碰撞距离和三维重建 | 动态场景更新与大空间扩展较困难 |
| 网格 / 表面模型 | 顶点、边与面 | 物体表面、渲染、碰撞和接触几何 | 构建和持续更新成本较高 |
| 隐式神经表示 | 坐标到密度、颜色或距离等函数 | 连续场景表达、新视角合成、细节重建 | 查询与训练成本、在线更新和可解释性受限 |
| 对象中心地图 | 带位置、属性和状态的对象实例 | “杯子在哪里”“门是否打开” | 依赖稳定检测、关联和对象状态维护 |
| 三维场景图 | 多层节点及其空间、语义关系 | 房间—区域—对象关系和高层查询 | 上游误差会沿层级传播，关系需要持续更新 |

### 占据、语义和关系不是一回事

三种地图回答的问题不同：

```text
占据地图：这里是空闲、被占据，还是未知？
语义地图：这里是什么类别或概念？
对象地图：这是哪个具体对象，它目前在哪里、状态如何？
场景图：对象、区域和房间之间存在什么关系？
```

例如，“托盘在桌上”是一条关系信息；“托盘区域不可通行”是占据或代价信息；“这是托盘”是语义信息。把它们混成一张没有明确查询接口的“大地图”，会让下游模块难以判断数据含义和新鲜程度。

### 为什么必须保留“未知”？

未被观测的空间不等于空闲空间。占据表示通常区分空闲、占据和未知：

- **空闲**表示传感器证据支持机器人可以通过或射线曾穿过。
- **占据**表示测量支持该位置存在物体或表面。
- **未知**表示系统尚无足够证据。

如果把未知默认当成空闲，机器人可能规划穿过从未看见的区域；如果全部当成占据，机器人又可能无法探索。未知状态因此同时影响安全和主动探索。

<a id="spatial-memory"></a>

## 机器人如何形成空间记忆？

**一句话理解：空间记忆不是保存所有历史帧，而是把跨时间的观测对齐、融合，并在世界变化时及时修正。**

### 定位、建图与 SLAM

| 问题 | 已知信息 | 需要估计的内容 |
| --- | --- | --- |
| 定位 | 已有地图与当前观测 | 机器人在地图中的位姿 |
| 建图 | 较可靠的机器人位姿与传感器观测 | 环境的空间表示 |
| SLAM | 地图和机器人位姿都不完全已知 | 机器人轨迹与地图，并处理累计误差 |

SLAM 能够提供坐标一致的轨迹和地图，但它不会自动理解“这是杯子”“杯子可以抓”或“杯子属于用户”。几何定位、语义理解和行动判断可以共享信息，却仍是不同能力。

### 自我中心与世界中心表示

- **自我中心表示**以机器人或当前相机为参照，适合局部避障、近距离操作和快速反应。
- **世界中心表示**以相对稳定的地图坐标系为参照，适合长期导航、跨房间记忆和对象重定位。

真实系统往往同时维护两者：局部表示追求及时更新，全局表示追求跨时间一致。机器人移动时，需要利用坐标变换把局部观测注册到全局地图，也需要在定位漂移或回环修正后同步更新相关状态。

### 静态地图为什么不够？

家庭、仓库和人机协作场景都不是静止世界。空间记忆需要区分：

- 长期稳定结构，如墙体、房间和固定设备；
- 可能移动的对象，如杯子、工具和箱子；
- 短时动态实体，如人员、车辆和正在运动的机械臂；
- 任务状态，如门已打开、托盘已占用或物体已被拿走。

系统不仅要“记住看过什么”，还要记录观测时间、置信度和更新规则。否则，精确但过期的物体位置仍会导致错误行动。

<a id="action-semantics"></a>

## 怎样从场景语义走向行动语义？

**一句话理解：机器人需要的不只是对象名称，而是与自身能力、当前任务和环境状态相关的可行动信息。**

### 可供性：物体允许做什么？

可供性描述环境或对象相对于行动者提供的交互可能，例如：

- 平面是否可站立、可放置或可通行；
- 杯把是否可抓，按钮是否可按，抽屉把手是否可拉；
- 某个接触区域是否适合当前夹爪、吸盘或手指；
- 当前姿态下，某个动作是否可达且不会碰撞。

可供性不是物体永远不变的标签。同一个杯子对双指夹爪和吸盘提供的抓取区域不同；一把被其他物体挡住的手柄在语义上仍是手柄，在当前状态下却可能不可操作。因此，可供性至少受到**对象状态、本体能力、动作类型和任务目标**共同影响。

### 开放词汇感知解决了什么？

传统封闭词汇模型只能识别训练时预先定义的类别。开放词汇感知尝试利用视觉—语言表征，通过文本查询定位更广泛的对象、属性或区域，例如“红色保温杯”“可以坐的地方”或“靠近水槽的清洁工具”。

它扩展了语言与感知之间的接口，但不意味着系统已经理解物理交互：

- 文本相似度高，不代表对象真的可抓或可承重；
- 能在图像中定位概念，不代表能获得准确三维位姿；
- 开放词汇结果仍可能出现误检、类别偏差和空间对齐错误；
- 新概念被识别后，仍需几何、状态、可供性和安全检查。

### 面向任务的状态压缩

完整传感器数据通常远大于规划器或策略真正需要的信息。感知系统可以将其压缩为任务状态，例如：

```text
目标对象：红色杯子 #3
对象位姿：基座坐标系中的位置与朝向
可见度：杯体清晰，杯把部分遮挡
候选交互：杯体侧夹；杯把抓取置信度低
周围状态：左侧有障碍，托盘区域空闲
不确定性：深度边缘噪声较高
建议动作：向右移动相机后重新估计
```

这种状态比一张原始图像更容易被下游使用，但也更容易因错误压缩丢失关键信息。因此，系统通常需要保留回查原始观测、置信度和来源时间的能力。

## 感知为什么也需要闭环？

**一句话理解：当当前观测不足以可靠行动时，机器人应通过移动、接触或重新观察主动获得信息。**

被动感知只处理传感器当前收到的数据；主动感知会选择动作来改善后续观测，例如：

- 移动相机或身体，绕开遮挡并获得新的视角；
- 调整光源、焦距或传感器姿态；
- 轻触物体，判断材质、接触位置或是否发生滑动；
- 推开遮挡物，确认目标是否存在；
- 在低置信度区域降低速度或请求人工确认。

一个更完整的闭环是：

```text
观测 → 建立任务状态 → 评估不确定性
  ↑                         ↓
结果验证 ← 执行动作 ← 选择行动或新视角
```

这里的行动既可能是完成任务的动作，也可能是专门为了获得信息的探测动作。空间智能因此不是单向的“先感知、后行动”，而是感知与行动相互塑造的循环。

## 贯穿示例：把红色杯子放入托盘

> 用户要求移动机械臂：“把桌上的红色杯子放入托盘。”

| 阶段 | 感知与空间系统要完成的工作 | 输出给下游的信息 |
| --- | --- | --- |
| 找到目标 | 根据语言描述检测并分割红色杯子 | 对象身份、掩码、置信度 |
| 恢复几何 | 融合深度或多视角信息，估计杯体表面与尺度 | 点云、深度、物体尺寸 |
| 估计位姿 | 将杯子从相机坐标系转换到机器人基座坐标系 | 带时间戳的 6D 位姿 |
| 理解场景 | 识别桌面、托盘、障碍以及对象间关系 | “杯子在桌上”“托盘内为空” |
| 判断交互 | 结合夹爪和遮挡判断可抓区域 | 候选接触区域与不确定性 |
| 主动补观测 | 杯把被遮挡时移动相机重新观察 | 更完整几何和更新后的位姿 |
| 执行中跟踪 | 物体或机器人移动时持续更新相对状态 | 对象轨迹、最新坐标变换 |
| 接触确认 | 用力觉或触觉确认夹持和滑动状态 | 接触、压力、滑动风险 |
| 结果验证 | 放置后重新观察托盘并更新对象地图 | 成功状态或失败原因 |

这个例子说明：感知系统并不是在动作开始前输出一次结果就结束。它需要贯穿发现、定位、交互和验证全过程，并在每次关键状态变化后更新空间记忆。

## 如何评估一个具身感知系统？

**一句话理解：离线感知精度是必要指标，但最终应检查它是否在正确时刻为行动提供了足够可靠的状态。**

| 评测层级 | 常见指标或检查项 | 不能单独说明什么 |
| --- | --- | --- |
| 对象感知 | Precision、Recall、mAP、IoU、跟踪一致性 | 目标是否具有可执行的三维位置 |
| 几何估计 | 深度误差、点云距离、重建完整度 | 地图是否具有正确语义和任务价值 |
| 位姿与定位 | 平移 / 旋转误差、ATE、RPE、重定位成功率 | 误差是否仍在具体动作容差内 |
| 地图质量 | 占据准确率、表面误差、地图一致性、更新延迟 | 下游是否能方便查询和使用 |
| 语义与关系 | 分割、检索、关系识别和开放词汇定位表现 | 物理可供性和安全性是否成立 |
| 系统性能 | 端到端延迟、更新频率、资源占用、数据新鲜度 | 感知错误会怎样影响行动 |
| 任务结果 | 导航成功率、抓取成功率、碰撞率、恢复率 | 失败具体来自感知、规划还是控制 |

评测时应把误差放回动作语境。五厘米定位误差对房间级导航可能可接受，对插孔装配却完全不可用；一帧分割错误对离线图片影响有限，在高速闭环中却可能引发错误接触。

### 最小评测闭环

1. 明确下游动作真正需要哪些状态和容差。
2. 分别测量传感器、单任务模型和空间表示的误差。
3. 检查时间戳、坐标变换和更新延迟是否满足闭环要求。
4. 在遮挡、光照变化、动态物体和新类别下进行压力测试。
5. 记录感知错误如何传播到规划、控制和任务结果。
6. 为低置信度、失跟踪和地图冲突设计降级或重观测机制。

## 常见故障与排查思路

| 现象 | 优先检查 | 常见根因 |
| --- | --- | --- |
| 图像中目标正确，三维位置却偏移 | 相机内外参、深度对齐、坐标变换 | 标定错误、深度和彩色图未对齐 |
| 静止物体在地图中出现重影 | 时间同步、位姿估计、运动畸变 | 多传感器时间错位、定位漂移 |
| 机器人反复把旧位置当作目标位置 | 对象关联、观测时间和地图更新策略 | 动态对象未从长期地图中失效 |
| 语义识别正确，但抓取经常失败 | 6D 位姿、可见表面、接触区域 | 只有类别信息，没有行动几何 |
| 点云完整，规划却认为无路可走 | 占据阈值、膨胀半径、未知空间处理 | 表示转换或机器人尺寸配置不当 |
| 开放词汇查询命中错误对象 | 文本歧义、视觉相似度和空间约束 | 只依赖语义相似度，未结合关系与几何 |
| 抓住物体后仍持续加力 | 触觉 / 力觉信号、阈值、控制时序 | 接触状态未进入闭环或反馈延迟 |
| 仿真感知稳定，真机波动明显 | 传感器噪声、材质、光照和标定 | 仿真域过于理想，缺少真实干扰 |

排查顺序应从数据是否新鲜、坐标是否一致、标定是否有效开始，再检查单任务模型、跨帧关联、地图更新和任务接口。直接替换更大的视觉模型，无法修复错误时间戳或坐标链。

## 常见误区

### 误区一：识别出对象类别，就完成了具身感知

类别只回答“是什么”。机器人还需要知道对象实例、位置、朝向、状态、可见度、可供性和不确定性，才能安全行动。

### 误区二：三维重建越精细，空间智能越强

精细重建可以改善几何细节，但不自动提供语义、动态更新、对象关系和任务接口。对许多实时任务，及时且可查询的简化表示比高保真模型更有价值。

### 误区三：未知区域就是没有障碍

未知只表示没有足够观测。把未知当成空闲会引入碰撞风险，把未知全部当成障碍又会阻止探索，需要结合风险和任务策略处理。

### 误区四：SLAM 已经解决了空间理解

SLAM 主要估计机器人轨迹并构建几何地图。对象语义、关系、可供性、动态状态和语言查询还需要额外能力。

### 误区五：开放词汇模型能够识别任意对象

开放词汇表示扩大了可查询概念范围，但仍受到训练分布、视觉歧义、尺度、遮挡和提示表达影响，也不能替代三维定位与物理验证。

### 误区六：可供性是物体固定不变的属性

可供性取决于本体、动作、任务和当前环境。对人可坐的椅子未必适合小型机器人攀爬；可抓的把手在被遮挡时也可能暂时不可操作。

### 误区七：融合模态越多，感知一定越可靠

多模态只有在标定、同步、质量评估和冲突处理正确时才会互补。错误融合可能把局部噪声传播到完整空间状态。

## 本章速记

- 具身感知的目标不是理解一张图，而是建立能够支持行动并持续更新的任务状态。
- 空间智能包含建立表示、持续更新和按需查询三类能力，不等同于高保真三维重建。
- RGB、深度、点云、本体状态、力觉和触觉各有盲区，多模态融合首先要保证标定、同步和不确定性处理。
- 检测、分割、跟踪、深度、运动和 6D 位姿估计回答不同问题，应按下游任务组合。
- 2D、2.5D、3D 和 4D 描述不同的信息范围，更高维不自动意味着更可靠。
- 点云、占据、表面、对象地图和场景图适合不同查询，不存在脱离任务的统一最优表示。
- 空闲、占据和未知必须区分；未知空间既关系安全，也决定主动探索。
- SLAM 提供轨迹与几何地图基础，但不会自动获得对象语义、关系和可供性。
- 可供性取决于对象状态、本体能力、动作和任务目标，不是静态类别标签。
- 开放词汇感知扩展了语义查询范围，但仍需几何定位、状态判断和物理验证。
- 主动感知通过移动视角、接触或重新观察减少不确定性，使感知进入行动闭环。
- 评测应从单任务精度延伸到数据新鲜度、表示质量、任务成功率和失败传播。

3. RGB、深度、IMU 和触觉分别能补充哪些信息？
4. 目标检测、实例分割和 6D 位姿估计的输出为什么不能互相替代？
5. 点云、占据地图、对象地图和三维场景图分别适合回答什么问题？
6. 为什么未知空间不能直接当作空闲空间？
7. SLAM、语义理解和空间智能之间是什么关系？
8. 为什么可供性会随机器人本体和任务变化？
9. 开放词汇感知解决了什么问题，又没有解决什么问题？
10. 当杯把被遮挡时，机器人可以怎样通过主动感知降低不确定性？
11. 为什么离线 mAP 更高的模型不一定带来更高的机器人任务成功率？

<details>
<summary>展开参考答案要点</summary>

1. 普通视觉任务通常处理单次观测并输出类别或位置；具身感知需要结合机器人状态、三维几何、时间变化、接触反馈和不确定性，形成可供行动使用并持续更新的状态。
2. 导航、抓取、语言查询和展示重建需要的信息粒度、更新频率和接口不同；表示应由下游查询、资源和容差决定。
3. RGB 提供纹理和语义，深度提供距离和局部几何，IMU 提供高频运动线索，触觉提供视觉遮挡下的接触、压力和滑动信息。
4. 检测给出粗位置，实例分割给出对象区域，6D 位姿给出三维位置与朝向；三者回答的问题和行动用途不同。
5. 点云描述采样表面，占据地图区分空闲、占据和未知，对象地图维护具体对象状态，三维场景图表达跨层级实体及关系。
6. 未知表示没有证据。将其当成空闲会增加碰撞风险，应根据安全要求、探索策略和新观测逐步更新。
7. SLAM 为轨迹和坐标一致的几何地图提供基础；语义理解赋予对象、属性和关系；空间智能还需要持续更新、按需查询并服务行动。
8. 可供性表达行动者与环境的关系。不同夹爪、尺寸、可达范围、动作和上下文会改变同一对象可执行的交互。
9. 它允许用训练标签集之外的文本概念查询视觉或三维场景，但不保证三维位姿、物理属性、可供性和动作安全正确。
10. 可以移动相机或机器人改变视角、调整照明、绕开遮挡，必要时进行轻触探测，再融合新观测更新位姿和可供性判断。
11. 机器人还受到延迟、坐标误差、跨帧稳定性、动作容差、置信度校准和失败恢复影响；离线检测精度只覆盖其中一部分。
