# 08_世界模型与预测控制

> 理解模型如何预测环境变化、想象行动结果，并把预测能力用于机器人决策。

## 本章定位

第 07 章的机器人已经抓住红杯，准备把它放进左边的托盘。如果直接横移，杯底可能碰到托盘边缘。如果先抬高再横移，路径更长，却可能留出更大的空间。世界模型可以预测不同动作的后果，规划器据此比较动作方案。

- 根据控制任务判断模型应保留哪些状态、预测哪些变化。
- 解释预测结果如何用于动作选择或策略训练。
- 描述模型预测控制如何利用真实反馈逐步修正计划。
- 设计评测，判断预测误差是否会改变动作选择和任务结果。

## 动作条件预测回答什么问题？

本章讨论可用于机器人决策的世界模型。给定当前观测所估计的状态和候选动作，模型预测下一状态、观测或与任务相关的量，例如杯子位姿、接触状态、任务代价。反复用预测状态和后续动作推进，就得到一条假想轨迹（rollout）。存在遮挡、未知摩擦或外部扰动时，模型也可以输出多个可能结果或概率分布。

**观测**是传感器实际读到的信息，**状态**是预测所需的环境与本体信息。一张图可能同时符合「杯子夹稳」和「杯子正在滑动」两种情况。编码器可以结合历史画面、夹爪状态或触觉，估计夹持情况。模型能否区分这两种状态，取决于输入是否提供足够证据。

用同一起点分别输入「直接横移」与「抬高后横移」，可以检查预测是否体现动作差异。仅在训练集中观察到的动作上重放预测，较难发现模型对候选动作不敏感。如果训练数据几乎只有平稳搬运，模型对碰撞边缘或滑落的预测也需要额外验证。

<a id="representations"></a>

## 预测画面、物体状态还是潜在特征？

| 表示 | 抓杯示例 | 怎样判断是否适用 |
| --- | --- | --- |
| 像素或视频 | 预测夹爪、杯子和托盘在画面中的变化 | 检查物体身份、几何和接触事件是否随动作正确变化 |
| 显式状态 | 预测杯子位姿、速度或夹持状态 | 容易构造任务代价，依赖可靠的状态估计 |
| 潜在状态 | 编码观测后，在隐空间预测下一步特征 | 可省去逐帧图像解码，需要验证特征是否保留决策所需的信息 |

动作条件视频预测可以参与规划，例如比较不同推动动作会怎样改变图像中目标的位置。用于控制时，还需核对视频时间步与机器人动作的对应关系，并检查关键事件。背景几乎完全正确的一段视频，仍可能把杯底与托盘边缘的一次接触预测错。[Deep Visual Foresight for Planning Robot Motion](https://arxiv.org/abs/1610.00696)

潜空间预测允许规划器在压缩表示上比较候选动作。模型可以通过重建观测、预测奖励或学习任务价值等方式训练。任务相关的信息决定了压缩是否有效。例如把杯口朝向丢掉后，模型仍可能预测杯子大致会到哪里，却难以支持「保持杯口朝上」的约束。[Learning Latent Dynamics for Planning from Pixels](https://arxiv.org/abs/1811.04551)

<a id="mpc"></a>

## 模型预测控制怎样选动作？

模型预测控制（Model Predictive Control，MPC）在当前状态下求解一段有限时域内的动作，再用新的状态估计反复求解。动力学模型可以来自物理方程、系统辨识或机器学习。以学习得到的世界模型为例，一轮控制可以这样理解：

1. **估计当前状态。** 读入最新的杯子、夹爪和托盘状态。
2. **预测并比较候选动作。** 规划器可通过采样或优化产生候选序列，分别预测杯子的位置和接触结果。
3. **按目标与约束求解。** 比较到目标的距离、动作耗时与平滑性，并剔除违反可达性或安全约束的候选。若当前找不到可执行方案，由执行系统进入等待、停止或恢复流程。
4. **执行首个动作或短前缀。** 读取真实反馈，更新状态并重新规划。固定参数模型也能运行这套闭环，模型参数在线更新是另一项设计选择。

| 候选方案 | 假设的模型预测 | 规划判断 |
| --- | --- | --- |
| 直接横移 | 路径短，杯底可能擦到边缘 | 安全余量不足，排除 |
| 先抬高再横移 | 耗时略长，预计能越过边缘 | 选择并先执行抬升 |

抬升后，若新观测显示杯子在夹爪中倾斜，规划器应基于新状态重新比较后续动作。预测时域过短可能看不到托盘边缘之后的结果。时域拉长会增加计算成本，也可能放大多步预测误差。执行侧仍需根据实际观测落实碰撞监测和停止机制。[TD-MPC2: Scalable, Robust World Models for Continuous Control](https://arxiv.org/abs/2310.16828)

## 世界模型怎样参与策略学习和 VLA 执行？

- **用预测结果在线规划。** 部署时，规划器在世界模型里评估候选动作，再决定执行哪一段。VLA 可以提供初始动作候选或语言指定的子目标。
- **用想象轨迹训练策略。** 训练时，从真实经验编码出的状态出发，用模型生成多步假想轨迹，再据此优化策略和价值估计。部署时可以由策略直接给出动作。Dreamer 展示了这种做法。[Dream to Control: Learning Behaviors by Latent Imagination](https://arxiv.org/abs/1912.01603)
- **联合建模动作和未来。** 一些工作把这类方法称为 World Action Model（WAM）。阅读时先确认模型实际查询的是「动作给定后预测什么」「目标给定后输出什么」，以及推理时是否真的使用预测未来来比较动作。

动作分块提供一段未来动作。模型预测控制还会利用动力学和目标对候选动作求解。两者都可以在执行一小段后重新观察，所以判断系统用了什么机制，要看它生成了哪些中间结果，以及这些结果怎样影响最终选择。

<a id="evaluation"></a>

## 怎样评估预测对控制的帮助？

| 检验 | 可记录的结果 |
| --- | --- |
| 固定起始状态，改变候选动作 | 预测能否区分擦碰、绕过和放稳，预测排序是否与实测相符 |
| 比较单步和多步预测 | 杯子位姿误差、接触漏报率随预测步数怎样变化 |
| 检查少见状态 | 遮挡或轻微滑动时，置信度偏高的错误预测出现多少次 |
| 在相同预算下比较闭环方案 | 有无模型筛选时的放置成功率、碰撞、干预和决策延迟 |

优化器会倾向选择模型评价最高的动作。某条候选在历史数据中几乎没有出现时，高分可能来自模型误差。评测应检查规划器最终选中的候选，并按新物体、布局和接触条件分别报告结果。若预测有改进但实际决策超时，也应记录命令生效时的状态，判断收益能否在闭环中实现。

## 自检问题

1. 为什么只给一帧图像，可能无法预测杯子是否会滑落？
2. 比较「直接横移」和「先抬高」时，怎样检验模型是否真的使用了动作输入？
3. MPC 接收新观测后，通常更新的是哪部分？
4. 想象轨迹训练与在线规划分别在哪个阶段使用世界模型？

<details>
<summary>展开参考答案</summary>

1. 相似画面可能对应不同速度、夹持或接触状态。可以结合历史、本体状态和触觉。
2. 固定起点，改变动作序列，分别比对预测与实测的杯子位置、接触和任务结果。
3. 更新当前状态估计，并从新状态重新求解。只有设计了额外的在线学习环节才会更新模型参数。
4. 前者在训练时用假想轨迹优化策略。后者在执行时通过预测来比较当前动作候选。
