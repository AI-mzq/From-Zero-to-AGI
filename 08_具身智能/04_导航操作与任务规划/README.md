# 04_导航、操作与任务规划

> 理解机器人如何把“去哪里、做什么”的任务目标，逐层转化为可执行、可验证并能在失败后调整的真实行为。

## 本章定位

感知系统可以告诉机器人目标在哪里、周围有哪些障碍，却不会自动产生一套安全可行的行动。机器人还需要决定先做什么、调用哪项技能、身体经过哪些状态，以及执行结果是否真正满足任务目标。

本章围绕三类紧密关联、但不能混为一谈的能力展开：

- **导航**改变机器人自身在环境中的位置与朝向。
- **操作**通过接触改变物体、工具或环境的状态。
- **任务规划**把较长目标分解成带有前置条件、执行顺序和成功标准的步骤。

移动操作机器人需要将三者连接起来，但“导航到了目标附近”“机械臂存在无碰撞轨迹”和“整个任务已经完成”是三个不同层级的判断。真正可执行的系统必须让语义目标、空间约束、身体能力和实时反馈在同一闭环中不断对齐。

本章不推导搜索算法、采样规划或控制理论，也不展开某个导航栈、运动规划框架或机械手的使用教程。策略如何通过数据学习、模型如何直接生成动作，将在[机器人学习基础](../05_机器人学习基础/README.md)和[策略模型与动作生成](../06_策略模型与动作生成/README.md)中讨论。

## 读完本章，你应该能够

- 区分导航、操作、任务规划、运动规划、轨迹生成和控制的职责。
- 根据目标形式和场景条件，判断机器人需要哪类导航或操作能力。
- 分析高层任务如何通过技能接口和几何约束转化为可执行行为。
- 说明移动操作与长时程任务为什么需要状态监测、失败恢复和闭环重规划。
- 从任务完成、运动可行性、执行效率、安全性和恢复能力等层面评估机器人规划系统。

## 从任务目标到物理动作，需要经过哪些层级？

**一句话理解：高层规划决定做什么，运动规划决定身体怎样到达，控制负责让真实机器人跟随目标。**

```text
任务目标
  ↓ 分解步骤与约束
任务规划
  ↓ 选择可用技能
技能编排
  ↓ 求解空间与身体可行性
运动规划
  ↓ 加入时间、速度与加速度
轨迹生成
  ↓ 根据反馈持续修正
控制执行
  ↓ 检查环境和任务状态
结果验证与重规划
```

| 层级 | 主要问题 | 输入示例 | 输出示例 |
| --- | --- | --- | --- |
| 任务规划 | 先做什么、后做什么？ | “把红色杯子放入托盘” | 找杯子 → 接近 → 抓取 → 找托盘 → 放置 |
| 技能编排 | 当前可以调用哪项能力？ | 任务步骤、技能库、对象状态 | `navigate_to`、`pick`、`place` |
| 运动规划 | 身体经过哪些无碰撞状态？ | 起点、目标、机器人模型、规划场景 | 底盘路径或关节空间路径 |
| 轨迹生成 | 怎样在时间上满足运动限制？ | 几何路径、速度和加速度约束 | 带时间戳的位姿或关节轨迹 |
| 控制执行 | 怎样抵抗误差和扰动？ | 目标轨迹、实时状态反馈 | 速度、力矩或其他底层命令 |
| 结果验证 | 动作是否真的产生预期效果？ | 新观测、接触与任务状态 | 成功、失败、重试或重新规划 |

这些层级并非必须由完全独立的软件模块实现。端到端策略可能合并其中若干环节，优化式方法也可能联合求解轨迹和控制。但无论实现形式怎样变化，目标语义、几何可行性、动力学限制、实时反馈和成功验证仍然存在。

### 计划、路径、轨迹和策略有什么区别？

- **计划**通常描述一组达到目标的决策或步骤，可以是离散技能，也可以包含连续运动。
- **路径**描述机器人在空间或构型空间中经过哪些位置，不一定包含时间。
- **轨迹**在路径基础上加入时间、速度、加速度或更完整的动态约束。
- **策略**根据当前观测或状态决定下一步动作，因此能够对不同状态产生不同输出。

一串语言步骤是计划的一种表达，但它还没有自动满足可达性、碰撞、时间、接触和控制约束。反过来，一条无碰撞轨迹也不代表高层任务一定正确：机器人可能稳定地抓错杯子，或者把杯子放在并非用户指定的托盘中。

<a id="navigation"></a>

## 导航：机器人究竟要到哪里？

**一句话理解：导航不仅要找到一条路，还要在持续观测和动态约束下到达对后续任务真正有用的位置。**

### 不同导航任务的目标并不相同

| 导航任务 | 目标怎样给出 | 机器人需要解决的额外问题 | 例子 |
| --- | --- | --- | --- |
| PointNav | 坐标、方向或相对位移 | 定位、路径规划和避障 | 到达地图中的指定坐标 |
| ObjectNav | 对象类别或文本名称 | 语义搜索、实例发现和停止判断 | 找到一把椅子 |
| ImageNav | 目标地点或对象的参考图像 | 视觉匹配、实例消歧和视角变化 | 到达照片中的那扇门 |
| VLN | 自然语言路线指令 | 语言落地、地标识别和顺序理解 | 穿过走廊，在沙发前左转 |
| 探索 | 未知空间或信息增益目标 | 选择新区域、处理未知和更新地图 | 尽快了解陌生房间布局 |
| 覆盖 | 需要访问的区域集合 | 完整性、路径效率和重复率 | 清扫或巡检整个区域 |

ObjectNav 和 VLN 都涉及语言或语义，但两者不等同。ObjectNav 常以目标类别为终点，系统需要主动搜索可能的位置；VLN 则强调遵循带有地标和顺序关系的路线描述。探索和建图也不是导航的同义词：探索强调选择信息获取动作，建图负责表示环境，导航负责让机器人安全地到达目标。

### 一个典型导航闭环

```text
目标定义
→ 当前位姿与环境表示
→ 全局路径或搜索方向
→ 局部速度与避障动作
→ 底盘控制
→ 新观测与进度检查
→ 到达、恢复或重规划
```

| 环节 | 主要职责 | 常见失败 |
| --- | --- | --- |
| 目标解析 | 将坐标、对象、图像或语言转成可检查目标 | 目标歧义、对象实例选错 |
| 状态估计 | 提供机器人位姿、地图和局部障碍 | 定位漂移、地图过期 |
| 全局规划 | 在较大范围内生成通往目标的路线 | 地图不完整、路径穿过不可达区域 |
| 局部规划与控制 | 跟踪路线并响应附近障碍和动力学限制 | 振荡、卡住、窄通道失败 |
| 行为编排 | 管理重定位、清障、等待和重新规划 | 恢复动作循环、缺少退出条件 |
| 到达判断 | 确认机器人处于满足后续任务的状态 | 只靠距离判断，朝向或视野不合适 |

对移动操作机器人而言，“到达目标”不能只定义为距离对象足够近。基座还需要停在机械臂可达、相机看得见、身体不会碰撞并且存在撤离空间的位置。导航终点因此经常由后续操作反向约束。

<a id="manipulation"></a>

## 操作：机器人怎样改变物体状态？

**一句话理解：操作不是机械臂移动到一个点，而是通过受约束的接触，让目标对象产生预期状态变化。**

### 常见操作任务

| 操作类型 | 目标状态变化 | 主要约束 |
| --- | --- | --- |
| 抓取与放置 | 建立稳定夹持，并将对象移动到目标区域 | 抓取稳定性、可达性、碰撞、放置支撑 |
| 推、拉与拨动 | 不完全约束物体，通过接触改变位置或方向 | 接触点、摩擦、物体运动的不确定性 |
| 开门、开抽屉 | 改变铰链或滑轨等关节状态 | 机构约束、把手接触、力方向 |
| 插接与装配 | 让零件满足精确相对位姿和接触关系 | 小容差、力控、视觉遮挡、误差累积 |
| 工具使用 | 借助工具改变其他对象或环境 | 工具功能、握持方式、作用区域 |
| 灵巧操作 | 在手内改变物体位姿或接触模式 | 多指协调、滑动、滚动和高维控制 |
| 双臂协作 | 两个机械臂共同搬运、固定或装配 | 时序同步、闭链约束、负载分配 |

抓取是操作的重要入口，但不是操作的全部。许多任务需要在接触过程中持续调整力、姿态和动作方向；有些任务甚至不需要稳定抓住物体，例如推开遮挡物或拨动开关。

### 从抓取候选到成功放置

```text
目标与可供性
→ 生成候选抓取或接触方式
→ 检查可达、碰撞与稳定性
→ 规划接近和预抓取动作
→ 建立接触并确认夹持
→ 搬运过程中持续监测
→ 规划放置与释放
→ 验证对象最终状态
```

| 阶段 | 需要确认的问题 | 失败示例 |
| --- | --- | --- |
| 候选生成 | 哪里可以接触，夹爪姿态怎样？ | 抓点位于遮挡背面 |
| 可行性检查 | 机械臂能否到达，手臂和环境会不会碰撞？ | 抓取位姿正确但无可行接近路径 |
| 接近 | 末端怎样靠近而不提前碰到物体？ | 手腕撞到桌面或其他物体 |
| 建立接触 | 是否夹到目标，力度是否合适？ | 空抓、夹偏、挤压易碎物体 |
| 搬运 | 物体是否滑动，轨迹是否仍安全？ | 加速过大导致物体掉落 |
| 放置 | 支撑面是否空闲、稳定且满足任务关系？ | 杯子位于托盘边缘并倾倒 |
| 验证 | 对象是否已释放并处于期望状态？ | 夹爪打开但物体仍被卡住 |

抓取检测模型通常只给出一个或多个候选抓取位姿。真实系统还需要结合机械臂可达空间、夹爪尺寸、场景碰撞、接近方向、物体材质和任务用途筛选。**“存在高分抓取姿态”不等于“存在完整可执行的抓取—搬运—放置过程”。**

<a id="mobile-manipulation"></a>

## 移动操作：导航和机械臂为什么不能简单串联？

**一句话理解：底盘决定机械臂从哪里操作，机械臂的可达性、视野和接触要求又会反过来决定底盘应该停在哪里。**

最简单的系统可以先导航、再操作：底盘到达预设站位后固定，机械臂独立完成抓取。这种顺序方式易于实现和排查，但在空间狭窄、目标超出单次可达范围或需要全身协调时可能失败。

| 协同方式 | 典型做法 | 优势 | 局限 |
| --- | --- | --- | --- |
| 顺序协同 | 底盘移动完成后，机械臂再动作 | 模块边界清楚，易于复用现有导航和操作栈 | 站位选择错误会让机械臂不可达 |
| 交替协同 | 底盘和机械臂按阶段多次调整 | 能逐步改善视野与可达性 | 状态切换多，误差容易累积 |
| 联合规划 | 在统一状态空间中规划底盘和机械臂 | 可以利用全身自由度处理复杂约束 | 搜索空间更大，模型与计算要求更高 |
| 联合策略 | 根据观测直接产生全身协调动作 | 闭环响应自然，适合复杂交互 | 数据需求、解释性和安全验证更困难 |

### 好的基座站位需要同时满足什么？

- 底盘能够到达，并留出安全停止和转向空间。
- 机械臂对目标、接触区域和放置点具有可达性。
- 相机或其他传感器能够可靠观察目标和操作过程。
- 机器人本体、手臂和环境之间不存在不可接受的碰撞风险。
- 接触过程中的力和物体运动不会破坏底盘稳定性。
- 操作完成后仍存在撤离或继续执行下一步的路径。

所以，“导航到物体中心前方 0.5 米”只是启发式规则，并不适用于所有本体、对象和环境。面向操作的导航目标，应由可达性、可视性和安全余量共同决定。

<a id="task-planning"></a>

## 任务规划：机器人怎样决定先做什么？

**一句话理解：任务规划在离散步骤层面搜索达到目标的行动组合，并通过技能条件与真实世界连接。**

一个可执行技能不能只有名称，还需要明确接口：

| 技能字段 | 作用 | `pick(cup)` 示例 |
| --- | --- | --- |
| 参数 | 指明技能作用于什么对象或目标 | 杯子实例、候选抓取方式 |
| 前置条件 | 执行前必须满足的状态 | 杯子已定位、机械臂可用、夹爪为空 |
| 执行效果 | 成功后预计改变什么 | 杯子与夹爪建立持有关系 |
| 成功判据 | 怎样确认技能真的完成 | 视觉、夹爪状态或触觉确认已抓住 |
| 失败类型 | 为什么可能无法完成 | 不可达、碰撞、空抓、滑落、超时 |
| 恢复入口 | 失败后可以采取什么动作 | 重新感知、换站位、换抓点或退出 |

任务规划器可以在这些技能及其条件上进行组合。例如，如果 `place(cup, tray)` 要求机器人已经持有杯子，那么计划必须先安排能够建立该状态的步骤。如果杯子当前不可见，计划还要插入搜索、导航或主动感知。

### 常见任务组织方式

| 方式 | 基本思想 | 适合场景 | 主要局限 |
| --- | --- | --- | --- |
| 有限状态机 | 用状态和转移显式描述流程 | 步骤少、分支明确的固定任务 | 状态和转移增多后难以维护 |
| 行为树 | 用选择、顺序和条件节点组合可复用行为 | 需要反应式执行和模块复用的机器人系统 | 复杂数据依赖和全局优化表达有限 |
| 符号规划 | 用对象、谓词、动作条件和效果搜索计划 | 规则明确、需要组合多个离散技能的任务 | 世界建模成本高，难直接处理连续几何 |
| 分层任务规划 | 将抽象任务逐步展开为更具体子任务 | 任务具有稳定层级结构时 | 层级与分解规则通常需要设计 |
| 任务与运动规划 | 联合考虑离散技能和连续几何可行性 | 抓取、摆放、移动障碍等复杂操作 | 离散与连续搜索互相耦合，计算困难 |
| 学习或语言模型规划 | 从数据和语义知识中提出步骤或调用技能 | 开放语言指令、未预先枚举的任务表达 | 可行性、状态一致性和安全性不能只靠文本保证 |

### 为什么需要任务与运动规划？

任务规划可能提出：

```text
拿起杯子 → 把杯子放入托盘
```

但如果杯子被盒子挡住，或者某个抓取姿态没有无碰撞路径，这个离散计划就不可执行。任务与运动规划（Task and Motion Planning，TAMP）将离散决策与连续几何约束连接起来：选择哪个对象、哪种抓取、哪个站位和哪条运动路径，需要相互反馈，而不能永远先决定任务步骤、再独立求解运动。

这不意味着所有系统都必须运行一个统一的大型 TAMP 求解器。工程上也可以通过分层尝试、候选排序和失败回退进行近似协同。关键是让几何不可行性能够反馈给高层，而不是让系统在同一个错误步骤上无限重试。

### 语言模型可以直接完成任务规划吗？

语言模型擅长理解开放指令、补充常识和提出技能序列，但文本上的合理性不等于机器人可执行性。一个语言规划结果至少要经过以下约束：

- 只能调用机器人真实具备且获得授权的技能。
- 技能前置条件必须由当前状态验证，而不是由模型猜测。
- 对象身份、空间位置和关系要连接到感知与地图。
- 几何、碰撞、动力学和安全约束由相应模块检查。
- 每项技能都要有成功判据、超时和失败出口。
- 环境变化后应重新读取状态，而不是继续照着旧计划执行。

语言模型可以参与高层候选生成、任务分解和恢复建议，但可靠系统仍需要技能落地、状态验证和执行监控。类似 SayCan 的思路正是将语言模型提供的高层知识与机器人技能的可行性评价结合，而不是让语言模型直接替代物理约束。

## 长时程任务怎样在失败后继续？

**一句话理解：长时程规划的核心不只是生成更长的步骤，而是持续知道任务进行到哪里、世界发生了什么变化，以及何时应该换方案。**

```text
选择下一技能
→ 检查前置条件
→ 执行并监测进度
→ 验证预期效果
├── 成功：更新状态，继续后续步骤
├── 可恢复失败：局部修正或换技能参数
└── 状态已改变：重新感知并全局重规划
```

### 失败恢复需要分层

| 失败范围 | 例子 | 合理处理 |
| --- | --- | --- |
| 参数级 | 当前抓点不可达 | 换抓点、接近方向或站位 |
| 技能级 | 连续两次抓取失败 | 重新感知、调整物体或切换抓取方式 |
| 局部计划级 | 原路径被临时障碍堵住 | 等待、局部绕行或重算路径 |
| 任务级 | 目标对象被人拿走 | 更新世界状态，搜索替代对象或请求帮助 |
| 安全级 | 发生异常接触、传感器失效 | 立即停止或进入安全状态，不继续自动重试 |

恢复策略必须有预算和退出条件。没有重试上限的系统可能在错误状态中反复碰撞；任何失败都从头开始，又会浪费已经完成的步骤。更合理的做法是保留可靠的任务进度，只回退到受影响的最小层级，并在关键假设失效时重新规划。

### 为什么开环长计划容易失效？

假设单个技能成功率为 90%，十个技能全部一次成功的概率已经显著下降。真实任务中还存在感知误差、对象移动、动作延迟和状态关联错误。随着任务变长，小误差会逐步积累，因此系统需要：

- 在关键动作后验证对象、机器人和环境状态；
- 保存已完成子目标，而不是只保存原始指令；
- 区分“动作执行完毕”和“预期效果已经发生”；
- 在不确定性升高时主动重新观察或请求人类确认；
- 记录失败原因，避免重复选择同一不可行方案。

## 贯穿示例：把红色杯子放入托盘

> 用户要求移动操作机器人：“把桌上的红色杯子放入托盘。”

| 阶段 | 规划系统的主要工作 | 成功判据或失败入口 |
| --- | --- | --- |
| 解析目标 | 确认杯子实例、托盘和最终关系 | 目标无歧义；否则询问或继续感知 |
| 生成任务骨架 | 搜索杯子 → 接近 → 抓取 → 搜索托盘 → 接近 → 放置 | 技能均存在且顺序满足条件 |
| 搜索与导航 | 选择搜索区域，并到达面向杯子的候选站位 | 杯子可见、基座稳定、机械臂可达 |
| 选择抓取 | 生成抓取方式并检查接近路径 | 抓取稳定、无碰撞且符合夹爪能力 |
| 执行抓取 | 接近、接触、闭合夹爪并抬升 | 视觉或触觉确认杯子被稳定持有 |
| 导航到托盘 | 将持物后的机器人几何和风险加入路径约束 | 杯子未滑落，托盘仍可到达 |
| 规划放置 | 选择托盘内的稳定空闲区域 | 放置位姿可达且不会碰撞 |
| 执行与验证 | 放置、释放、撤离并重新观察 | 杯子位于托盘内且夹爪已释放 |
| 失败恢复 | 根据失败层级修改参数、技能或任务计划 | 恢复成功，或安全退出并报告原因 |

这一流程中的每个阶段都可能改变后续计划。杯子抓起后，机器人外形、负载和安全速度发生变化；托盘被移动后，旧的导航目标失效；放置后如果杯子倾倒，夹爪打开并不等于任务完成。

## 如何评估导航、操作与任务规划系统？

**一句话理解：需要同时评估单项能力、层级接口和端到端任务，不能用一条最短路径或一次成功抓取代表完整系统。**

| 评测层级 | 常见指标 | 需要补充关注的问题 |
| --- | --- | --- |
| 导航 | 成功率、SPL、路径长度、到达误差、碰撞次数 | 终点是否适合后续观察和操作 |
| 抓取与操作 | 抓取成功率、放置成功率、位姿误差、接触力、物体损伤 | 是否在新对象、遮挡和杂乱环境中稳定 |
| 运动规划 | 规划成功率、规划时间、路径长度、平滑性、最小安全距离 | 轨迹能否被真实控制器可靠跟踪 |
| 任务规划 | 合法计划率、步骤数、约束满足率、重规划次数 | 计划是否使用真实技能和最新状态 |
| 恢复能力 | 失败检测率、恢复成功率、恢复时间、重复失败次数 | 是否能够正确区分可恢复和安全级失败 |
| 端到端任务 | 完整成功率、完成时间、能耗、人类干预次数 | 各模块误差如何沿长时程任务累积 |

导航中常用的 SPL 将任务成功与路径效率结合，但它不会说明是否平稳、是否碰撞，也不会判断终点能否支持抓取。操作成功率同样需要明确成功条件：夹爪闭合、物体被抬起、搬运后未滑落和最终放置正确，是不同强度的指标。

### 最小评测闭环

1. 明确目标状态、失败状态和允许的人类干预。
2. 分别评估导航、操作、技能执行和任务规划能力。
3. 检查模块交接时的坐标、对象身份、状态和时间信息。
4. 在遮挡、动态障碍、新物体和目标移动条件下测试。
5. 注入可恢复故障，验证系统能否检测并选择正确恢复层级。
6. 统计完整任务的成功率、时间、安全事件和失败归因。

## 常见故障与排查思路

| 现象 | 优先检查 | 常见根因 |
| --- | --- | --- |
| 导航显示成功，机械臂却够不到目标 | 导航终点、机械臂可达空间、视野和朝向 | 只按底盘距离设置目标，没有面向操作选站位 |
| 抓取姿态看起来正确，却没有可执行路径 | 规划场景、自碰撞、接近方向和关节限位 | 抓取候选未经过完整运动可行性检查 |
| 机器人反复规划，却始终停在原地 | 局部规划、控制接口、恢复条件和安全状态 | 路径可行但控制受限，或恢复行为循环 |
| 语言计划步骤合理，执行时连续失败 | 技能库、前置条件、对象落地和权限约束 | 文本步骤没有连接真实技能与当前世界状态 |
| 第一步成功后，后续动作使用了旧状态 | 状态更新、对象关联、坐标和观测时间 | 计划执行器未验证技能效果 |
| 抓住物体后导航频繁碰撞或急停 | 持物后的碰撞几何、负载和速度限制 | 仍按空手模型规划和控制 |
| 系统一直重试同一动作 | 失败分类、重试预算和候选去重 | 没有记录失败原因或替代方案 |
| 仿真长任务成功，真机很快中断 | 感知噪声、控制误差、接触和恢复逻辑 | 仿真简化了执行误差，模块失败概率在真机累积 |

排查时应先确定失败发生在哪一层：目标是否正确、技能前置条件是否满足、运动是否可行、轨迹是否被执行、动作效果是否验证。只观察最终“任务失败”很难判断应该改感知模型、规划器、控制器还是技能接口。

## 常见误区

### 误区一：导航就是在地图上搜索最短路径

真实导航还包括定位、局部避障、运动约束、动态更新、到达判断和恢复。最短几何路径也可能过窄、不平滑或不适合后续操作。

### 误区二：机械臂到达目标位姿就完成了操作

操作关注物体状态是否按预期改变。到达位姿后仍可能空抓、滑落、夹坏物体或放置不稳。

### 误区三：抓取分数最高的候选一定最好

抓取分数通常只覆盖部分稳定性或数据分布。系统还需考虑可达性、接近路径、碰撞、夹爪能力和后续搬运任务。

### 误区四：高层任务规划与运动规划可以完全分开

离散步骤可能因几何约束不可执行。站位、抓取方式、对象顺序和运动路径常常需要互相反馈，这也是 TAMP 存在的原因。

### 误区五：语言模型生成合理步骤，就完成了机器人规划

语言模型可以提出候选步骤，但无法仅凭文本保证技能存在、对象正确、路径无碰撞或动作安全。计划必须被真实状态和执行模块约束。

### 误区六：重规划就是从头再生成一次完整计划

局部失败优先进行参数级或技能级恢复；只有目标、环境结构或关键假设改变时，才需要更高层重规划。无差别从头规划会丢失进度并重复动作。

### 误区七：单项能力很强，组合系统就会同样可靠

长任务的失败常来自模块接口和误差累积。对象身份错位、状态未更新或成功判据不一致，都可能让多个高精度模块组合后仍然失败。

## 本章速记

- 导航改变机器人自身位置，操作改变对象或环境状态，任务规划决定步骤和技能顺序。
- 高层任务需要经过技能编排、运动规划、轨迹生成和控制执行，才能成为真实动作。
- 计划、路径、轨迹和策略描述不同层级的问题，不能互相替代。
- PointNav、ObjectNav、ImageNav、VLN、探索和覆盖具有不同目标定义与评测方式。
- 面向操作的导航终点还要满足机械臂可达、传感器可视、碰撞安全和后续撤离要求。
- 抓取位姿只是操作过程的一部分，还需要接近、接触确认、搬运、放置和结果验证。
- 移动操作中，底盘站位影响机械臂可达，操作约束也会反向决定导航目标。
- 可执行技能应包含参数、前置条件、预期效果、成功判据、失败类型和恢复入口。
- TAMP 连接离散任务决策与连续几何可行性，不要求所有系统都采用单一统一求解器。
- 语言模型能够辅助高层任务分解，但必须受技能库、当前状态、几何和安全机制约束。
- 长时程可靠性来自持续验证和分层恢复，而不是一次生成更长的开环计划。
- 评测应覆盖单项能力、模块交接、失败恢复和端到端任务结果。

7. 一个可靠的机器人技能接口应包含哪些信息？
8. TAMP 为什么需要让离散任务决策与连续几何约束相互反馈？
9. 语言模型产生的任务步骤还需要经过哪些落地检查？
10. 什么时候适合局部恢复，什么时候需要全局重规划？
11. 为什么导航成功率、抓取成功率都很高，完整长任务仍可能频繁失败？

<details>
<summary>展开参考答案要点</summary>

1. 导航主要改变机器人自身在环境中的位姿；操作通过接触改变对象或环境状态；任务规划决定达到目标所需的步骤、顺序和技能。
2. 任务规划输出离散步骤或技能序列；运动规划输出空间中的可行路径；轨迹生成加入时间与运动限制；控制器根据反馈产生底层命令并修正误差。
3. ObjectNav 通常要求找到某类对象，需要进行语义搜索和停止判断；VLN 要求遵循带地标和顺序的语言路线，需要持续将指令片段与视觉环境对齐。
4. 后续操作还要求机械臂可达、相机可见、身体不碰撞并有继续运动的空间；仅距离接近不保证这些条件。
5. 候选可能超出机械臂可达范围，接近路径发生碰撞，夹爪与物体不匹配，或抓取后没有安全搬运路径。
6. 顺序协同适合站位明确、底盘停止后机械臂可独立完成的任务；联合规划适合狭窄空间、超出单次可达范围或需要全身协调的任务。
7. 至少应包含参数、前置条件、执行效果、成功判据、失败类型、超时和恢复入口。
8. 离散计划中的步骤可能因不可达、碰撞或接触限制而无法执行；几何求解结果需要反向修改对象顺序、抓取方式或站位。
9. 需要检查技能是否真实存在、前置条件是否满足、对象是否正确落地、运动是否可行、安全和权限是否允许，以及执行效果是否得到验证。
10. 抓点、站位或局部路径失效时可优先局部恢复；目标消失、环境结构改变或关键任务假设失效时应进行更高层重规划。
11. 长任务需要多个模块和技能连续正确工作，单项误差、接口错位和状态更新失败会沿执行链累积，最终成功率不能由单项指标直接推出。
