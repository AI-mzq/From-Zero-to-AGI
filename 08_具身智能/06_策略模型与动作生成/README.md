# 06_策略模型与动作生成

> 研究模型如何表示、预测和生成机器人动作，并在闭环中稳定执行。

## 本章定位

上一章用抓杯任务解释机器人从哪里获得训练信号。这一章从执行时的一帧画面开始。夹爪看到了红杯，策略可以输出下一步位移，也可以生成一段接近和夹持动作。输出是什么、生成多少步、执行几步后重新观察，分别影响动作精度、连贯性和纠偏速度。

## 读完本章，你应该能够

- 根据任务精度和控制接口选择动作表示。
- 从论文中读出策略的条件输入、动作生成方式和执行方式。
- 结合动作频率、观测延迟和任务变化速度判断何时重新推理。
- 通过闭环评测定位动作失效，并判断多任务策略的泛化范围。

<a id="action-representation"></a>

## 动作表示决定了控制接口

抓杯时，“夹爪向前一点”必须具体到参考坐标系、位移量和执行周期。同一个技能可以通过不同层级的输出实现。层级越高，下游通常承担越多的几何求解和运动执行。

| 表示 | 抓杯示例 | 执行侧要处理什么 |
| --- | --- | --- |
| 关节控制量 | 各关节的目标位置、速度或力矩 | 跟踪或施加指定控制量，检查关节和驱动限制 |
| 末端位姿或增量 | 夹爪沿工具坐标系前移，同时保持朝向 | 坐标变换、逆运动学或笛卡尔控制、可达性检查 |
| 离散动作 | 前移、后退、闭合、停止 | 映射到有限的动作原语及其执行条件 |
| 关键点或航点 | 指定杯把附近的接近点和抬升点 | 补足姿态、路径和时间约束 |
| 轨迹 | 按时间排列的关节或末端目标 | 插值、跟踪，并监测当前状态是否仍允许执行 |

动作 Token 是模型内部的编码方式。它可以表示离散原语，也可以表示量化的连续控制量或经编码的动作片段。执行时需要解码。量化较粗时，小幅纠偏可能被舍入，精细操作尤其需要检查实际分辨率。

对于连续动作，训练数据和部署接口应约定绝对目标或相对增量、坐标系、旋转表示、单位、归一化范围和夹爪语义。相同的输出数组，在工具坐标系中表示向前，在基座坐标系中可能对应另一方向。速度命令还需要与实际生效时间一起解释。

<a id="action-generation"></a>

## 策略模型怎样生成动作？

杯子左右两侧都可接近时，同一观测可能对应两条合理路线。若监督数据混合左右示范，使用平方误差回归单一动作序列可能得到两条路线之间的折中，甚至碰到杯子。可以用更明确的目标条件区分路线，也可以让策略表示多种可能的动作。

| 方法 | 生成过程 | 部署时关注 |
| --- | --- | --- |
| 直接回归 | 从当前条件预测一个动作或整段连续动作 | 一次前向通常即可输出，需检查多种示范行为被平均后的结果 |
| 自回归 | 根据观测和已生成的动作元素逐个预测下一个元素 | 生成顺序和序列长度影响延迟，早期预测影响后续结果 |
| 条件扩散 | 从噪声出发，在观测条件下迭代去噪得到动作序列 | 去噪步数、推理延迟和采样稳定性 |
| Flow Matching | 学习随生成时间变化的向量场，推理时从噪声出发数值积分得到动作 | 积分步数及其对延迟和输出质量的影响 |

Transformer 可以编码观测、解码动作块，也可以作为扩散或流模型的骨干。描述策略时，可以分别说明**网络结构、生成机制和动作表示**。ACT 用 Transformer 在条件变分自编码器框架下预测动作块，适合用来理解整段输出与时间集成。Diffusion Policy 在观测条件下迭代生成动作序列，并结合滚动时域执行。π₀ 展示了用 Flow Matching 生成连续动作块的做法。[ACT](https://arxiv.org/abs/2304.13705) · [Diffusion Policy](https://arxiv.org/abs/2303.04137) · [π₀](https://arxiv.org/abs/2410.24164)

Flow Matching 中的生成时间描述样本从噪声向动作分布演化的过程。动作序列中的时间索引描述机器人何时执行各步。向量场作用在生成中的动作样本上，其数值由生成过程使用，最终得到的动作才由控制接口解释。[Flow Matching for Generative Modeling](https://arxiv.org/abs/2210.02747)

<a id="closed-loop"></a>

## 动作块预测多远，闭环又执行多久？

动作分块（Action Chunking）让策略在一次推理中输出连续多步动作。接近杯子时，连续几步可以共同表达一段连贯的接近轨迹。进入接触阶段后，杯子的轻微移动就可能让先前预测的夹持位置失效，此时需要及时使用新观测。

| 时间量 | 表示什么 |
| --- | --- |
| 观测窗口 | 每次推理参考多长的观测历史 |
| 预测地平线 | 一次推理输出多少未来动作 |
| 执行地平线 | 每次实际执行多少步才用新计划替换 |
| 动作频率 | 执行端以多高频率消费动作目标 |

假设动作目标以 20 Hz 执行，每次预测 16 步、只执行前 4 步。预测覆盖约 0.8 秒，理想情况下每 0.2 秒就可用新动作块更新一次。若采集、推理和通信耗时使系统错过更新时间，实际更新间隔就会变长。底层伺服可在更高频率上跟踪目标。

```text
读取观测 → 预测动作块 → 执行前几步 → 读取新观测 → 重新预测
```

这种滚动执行方式可以用新观测纠正旧计划。ACT 的时间集成是另一种处理方式：多次推理可能为同一执行时刻给出重叠预测，系统可加权合并这些预测。若新旧动作指向不同接近路线，应检查合并后是否仍可执行。真机还应记录观测时间、命令生效时间和动作块切换点，以便区分模型判断失误与输入过期。

<a id="generalization"></a>

## 单任务、多任务和通用策略如何比较？

单任务策略可以在已知条件下专注抓杯。多任务策略共享模型，通过任务 ID、目标图像或语言等条件选择抓杯、放置等行为。通用策略追求在更丰富的任务、场景或本体上复用，其适用范围需要用测试条件说明。

评估时可以分别改变杯子的形状、桌面环境、任务指令或机器人本体。换杯子成功只验证了对应的对象变化。换机械臂还涉及动作维度、坐标系、夹爪结构和控制接口，通常需要动作适配，并重新验证。语言和视觉如何共同表达任务条件，见下一章。

<a id="evaluation"></a>

## 用闭环回放区分模型、接口与时序问题

| 现象 | 优先核查 |
| --- | --- |
| 夹爪总沿错误方向移动 | 坐标系、单位、旋转和反归一化是否与训练约定一致 |
| 杯子移动后，夹爪仍追着旧位置 | 观测时间戳、推理延迟和动作队列中剩余的旧目标 |
| 动作块交接时突然抖动 | 新旧动作的起始状态、时间索引和切换处的速度变化 |
| 到达抓取点却没有稳定夹持 | 夹爪动作语义、接触反馈和把成功判据写入评测的方式 |
| 原场景成功，换杯后频繁失败 | 拆开检查视觉识别、动作精度和训练数据覆盖 |

对比两种动作生成方法时，应尽量固定训练数据、动作表示、执行频率与测试起点。若研究重点是动作块长度，可固定预测地平线并改变实际执行步数，同时记录任务成功率、扰动后恢复率、推理延迟和安全停止次数。先在仿真或受控环境验证，再逐步扩大真机测试条件。

## 自检问题

1. 同一个位姿增量在工具坐标系和基座坐标系下为何可能产生不同动作？
2. Transformer、扩散和动作 Token 分别描述策略的哪个方面？
3. 策略预测 16 步却只执行 4 步，剩余预测有什么作用？
4. 如果接触阶段经常抓偏，怎样区分推理过慢与策略本身预测不准？

<details>
<summary>展开参考答案</summary>

1. 两个坐标系的轴方向可能不同。执行端需要按训练约定转换动作，再交给控制器。
2. Transformer 描述网络结构，扩散描述生成机制，动作 Token 描述内部动作编码。
3. 后续步与前几步一同表达一段连贯运动。重新观测之后，可以用新的预测替换尚未执行的部分。
4. 回放观测时间和命令生效时间，查看预测是否匹配当时画面，再对比当前状态。若预测本身正确但生效时目标已变，优先排查延迟和队列。

</details>
