# 10_仿真与 Sim-to-Real

> 在可控环境中训练和验证策略，并缩小仿真世界与真实世界之间的差距。

## 本章定位

红杯在仿真中被稳稳夹起，真机却在抬升时滑落。可能是仿真的杯壁摩擦偏大，也可能是夹爪的实际夹紧力较小，或闭合命令还没执行完就开始抬升。要让仿真训练产生可迁移的技能，需要把这些差异转化为可测量、可调整并能验证的假设。

本章从仿真任务的组成出发，讲清现实差距、系统辨识、域随机化与适配方法，再用抓杯任务组织真机验证流程。

## 读完本章，你应该能够

- 为具体任务确定仿真中需要建模的对象、传感器、控制与评价接口。
- 根据失败现象定位视觉、接触、动力学或时序差异。
- 结合真实测量选择系统辨识、随机化和目标域适配方法。
- 设计分阶段迁移测试，并报告真实交互预算与测试条件。

<a id="environment"></a>

## 仿真环境由哪些部分组成？

| 组成 | 主要职责 | 抓杯任务中的检查 |
| --- | --- | --- |
| 物理引擎 | 计算动力学、碰撞和接触 | 质量、惯量、摩擦、碰撞形状和接触求解 |
| 场景与机器人资产 | 描述几何、关节、材质和传感器安装 | 杯壁厚度、夹爪开口和相机外参 |
| 任务环境 | 定义初始化、观测、动作、奖励、终止与重置 | 什么情况下算夹起、放稳或失败 |
| 控制与传感器接口 | 把策略输出转成控制，生成可用观测 | 控制模式、采样频率、噪声和延迟 |

物理步长决定每次推进多少仿真时间，控制周期决定策略目标何时更新，渲染频率决定相机观测何时产生。它们可以不同，需要明确调度关系。接触求解参数和步长也会影响稳定性，改变这些配置后应重新验证抓取和放置行为。[MuJoCo 仿真与建模文档](https://mujoco.readthedocs.io/en/stable/programming/simulation.html)

数字孪生通常强调与特定真实设备或场景保持对应，并利用真实测量校准或更新模型。对抓杯而言，要先确定需要复现的行为精度，再决定建模投入。模型可以重点校准夹爪、杯子和接触区域，同时保留部署时实际可获得的观测。

训练时，仿真可以向价值网络提供真实物体位姿等特权信息。若部署策略只使用相机和本体观测，应在评测时按同样条件供给输入。否则额外状态会改变任务难度，使迁移结果难以解释。

<a id="reality-gap"></a>

## 现实差距从哪里产生？

| 差异来源 | 典型变化 | 可能影响 |
| --- | --- | --- |
| 视觉 | 光照、纹理、反射、背景、相机成像 | 红杯定位、边缘识别和遮挡判断 |
| 几何与标定 | 碰撞形状、关节零位、传感器安装 | 抓点偏移、提前碰撞或目标不可达 |
| 动力学与接触 | 质量、惯量、摩擦、柔性和夹持力 | 滑落、反弹、夹持不稳 |
| 执行器与控制 | 增益、死区、回差、速度和力限制 | 轨迹跟踪滞后、超调或夹爪未闭合 |
| 传感与通信 | 噪声、丢帧、时间偏移和命令延迟 | 策略使用旧状态或错过接触变化 |

这些差异可能同时存在。真机夹起后滑落时，可先核查闭合时间和夹爪反馈，再用受控抓取比较载荷与摩擦条件。若尚未接触就已抓偏，先检查相机标定和动作坐标系。通过分阶段测量缩小原因范围，更容易确定下一次仿真实验该改哪些参数。

<a id="transfer"></a>

## 系统辨识、域随机化和域适配怎样使用？

### 系统辨识

系统辨识利用真实输入与输出估计模型参数。例如记录关节对阶跃目标的响应、夹爪闭合耗时和不同负载下的跟踪误差，再拟合执行延迟或等效动力学参数。估计结果依赖测量是否充分，不同参数也可能产生相近的响应，因此应在额外的动作和负载条件下验证。

### 域随机化

域随机化（Domain Randomization）在训练中改变一组环境参数，让策略接触多种条件。视觉随机化可改变背景、光照或纹理，动力学随机化可改变质量、摩擦和执行延迟。相关早期工作分别研究了视觉定位与物体推动的迁移。[视觉域随机化](https://arxiv.org/abs/1703.06907) · [动力学随机化](https://arxiv.org/abs/1710.06537)

范围可以依据测量和预期部署变化设置。例如同一刚性杯子的质量通常在一次 episode 内保持一致，测量噪声则可能随时间变化。随机化还需考虑参数之间的关联。过宽的范围会产生任务无解或物理上不合理的组合，影响训练效率和策略表现。

### 域适配与真机微调

域适配（Domain Adaptation）利用目标域数据调整表征、输入映射或模型，使其适应真实环境。视觉适配可使用真实图像，动作策略微调通常还需要与本体对应的示范或交互监督。完成校准和系统辨识后，也可以围绕剩余不确定性随机化，再通过少量真机数据微调。

仿真与真机的混合比例应结合任务覆盖和闭环效果决定。可以固定目标域数据和独立评测，改变仿真数据的采样权重，观察新条件收益和原有技能是否退化。数据组织与版本管理见[机器人数据工程](../09_机器人数据工程/README.md)。

<a id="validation"></a>

## 从仿真策略到真机任务

1. **对齐任务和接口。** 统一动作单位、坐标系、控制频率和成功条件，确认部署时能获得策略使用的输入。
2. **测量局部响应。** 在受控范围验证空载运动、夹爪闭合和传感时序，记录真实响应与仿真的差异。
3. **建立仿真基线。** 分别测试标称参数与随机化参数，并用独立场景和种子评估。
4. **分阶段测试真机。** 从接近、接触、抬升逐步扩展到搬运和放置，采用适合本体的速度、力和工作空间限制。
5. **回放并修订。** 根据失败证据更新参数、随机化范围或目标域训练数据，再用保留测试集比较。

```text
真实测量 → 校准与辨识 → 仿真训练和独立评测
   ↑                              ↓
失败回放与假设验证 ← 分阶段真机测试
```

改动需要关联到可验证的现象。例如真机只在抬升较快时滑落，可以比较不同抬升加速度的结果，检查夹紧力和负载响应。修改仿真摩擦参数后，再确认它能解释这一规律，并在保留速度或新杯子上测试。

<a id="diagnosis"></a>

## 迁移结果怎样诊断和复现？

| 现象 | 可比较的证据 |
| --- | --- |
| 仿真稳定，真机接触前就偏移 | 相机标定、机器人零位、同一命令下的末端实际位置 |
| 抓住后滑落 | 夹爪闭合时长、夹持反馈、负载、抬升加速度和接触参数 |
| 仿真动作流畅，真机发生振荡 | 控制模式、增益、目标更新周期、延迟和动作切换 |
| 仿真换背景仍成功，真实反光杯失败 | 成像条件、材质覆盖和目标定位误差 |

结果报告应同时给出仿真和真机成功率、试验次数、阶段失败比例、干预次数与执行时间。明确策略是否接触过目标机器人数据、用了多少真实示范或交互，以及哪些场景用于调参、哪些留作最终测试。最终测试反复用于调整随机化范围后，应补充独立测试条件。

复现记录包括仿真器与资产版本、物理和控制配置、随机化分布、种子、策略和数据版本、真机标定与硬件配置。并行仿真能增加采样量，实际收益还需要结合接触行为、重置成本、训练效率和真机结果判断。

## 自检问题

1. 为什么仿真里任务成功，仍需要检查策略能否获得同样的部署输入？
2. 抓杯在真机抬升时滑落，你会先收集哪些证据？
3. 一次 episode 内的质量变化与逐步传感噪声应怎样分别建模？
4. 怎样比较零真机训练迁移与真机微调后的表现？

<details>
<summary>展开参考答案</summary>

1. 仿真可提供精确状态等额外信息。部署输入缺失或质量变化会改变策略行为，应按实际可获得的观测评测。
2. 核查夹爪命令、闭合耗时和反馈，再比较夹紧力、负载、摩擦与抬升加速度。
3. 刚性对象质量通常在 episode 开始时采样并保持，噪声按传感器特性随时间生成，也可具有时间相关性。
4. 固定独立测试条件，分别记录真实示范和交互预算、适配模块及成功率，说明训练使用过哪些目标域数据。

</details>
