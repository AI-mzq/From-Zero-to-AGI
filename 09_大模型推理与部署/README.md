# 09. 大模型推理与部署

> 从一次请求到 GPU 集群，理解大模型如何稳定、高效、低成本运行。

**By：猫先生 of「魔方AI空间」**

## 板块定位

模型能够生成文本，不等于它已经成为可用的在线服务。真实系统还要处理排队、批处理、显存、缓存、并发、尾延迟、故障和成本。

本板块沿着一次推理请求的执行链，连接服务入口、请求调度、模型执行、GPU 资源与系统运维。

## 学习目标

沿着这条主线，你将逐步能够：

- 描述一次在线推理请求的主要处理阶段。
- 用统一指标比较延迟、吞吐和服务质量。
- 解释 KV Cache、批处理和调度为什么影响并发能力。
- 判断瓶颈更可能来自计算、显存、通信还是服务治理。
- 按负载和系统约束理解推理框架，而不是只比较跑分。

## 核心知识地图

```text
用户请求
  → API 与队列
  → 批处理与调度
  → Prefill / Decode
  → KV Cache
  → 推理引擎与模型执行
  → GPU、通信与集群资源
  → 监控、容量与成本
```
